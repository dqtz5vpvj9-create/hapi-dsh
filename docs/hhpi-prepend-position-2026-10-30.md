# Prepend position correction, 2026-10-30

The reported failure is a viewport landing at newly prepended content instead of retaining the text being read. Two regressions reproduced it in the installed official implementation before the fix:

- A nested `call:child` anchor was passed to the virtualizer, which only knows Conversation nodes, groups and virtual rows. Resolving the current row but retaining the unknown inner key did not keep that row mounted.
- The coordinator invoked `correct` after notifying stores, before React committed their new row order. The real mounted desktop row still had index 145 when the new model required 305; mobile was 142 versus 302. A source-page count or successful RPC could not detect this ordering error.

The optional complete-window UI publisher now flushes React publication before correction. The viewport retains the stable semantic owner, resolves its new virtual row after regrouping, carries that owner through position memory, and restores the precise inner offset after a necessary remount. A removed inner anchor cannot leave a pending restoration that revives on a later layout. Commit-time measurement becomes the content-preservation position.

The mounted component contract checks actual DOM/model order at correction on every one of six prepends. The viewport contract checks nested-tool identity, semantic pinning, exact remount landing, temporary-pin release and cancellation when a subcall disappears. Explicit jsdom geometry remains a fixture, not browser evidence.

The browser lab uses the installed official bundles, production HHPI reader and shared cache, with synthetic source IO. Its history includes complete tool/PTC/result lifecycles as well as 1,440 user messages. The live probe holds each read response until genuine input scrolling settles, samples the current DOM anchor, then checks its offset after the row-order publication before issuing another gesture. It does not write production conversations or alter DOM geometry. Subsequent gestures must still expose six consecutive earlier source bodies and read the resident tail without fetching it again.

The installed-source contracts passed all 12 cases. The Chromium component lab passed on desktop 1440×900 (15.36 seconds) and mobile 390×844 (31.68 seconds). In each scenario, all six body-bearing prepends retained the measured text at exactly 0 CSS pixels displacement; Chat grew from 154 to 1,078 nodes while the other Pane stayed at 154. Source audits verified all six contiguous 160-event intervals and their complete tool lifecycles. Drafts, composition input, cached traversal, return to latest and resident-tail reading passed. The measured anchors in these runs were user-message nodes, so these browser results do not claim six nested-tool-anchor landings; the exact nested anchor and remount lifecycle are exercised by the viewport contract.

The first lab report failed because its expected row count omitted the official assistant-step node, and a one-gesture travel assumption did not traverse a tool group on mobile. Those reports were retained. Corrected probes select visible user nodes and leaf text anchors, verify all 154 expected nodes per page, and use at most four actual gestures to reach that page's body. The 2-pixel limit and 60-second scenario budgets were unchanged.

The first production release (`9c995ec70f2d3622`, source extension `0f6965a0169f`) also retained all twelve measured anchors at 0 pixels across desktop/mobile six-page reads, including three actual nested-tool anchors. Each scenario made seven source reads; returning to latest and reading its resident tail made zero additional reads. Its overall result remained failed because frame gaps reached 217 milliseconds on desktop and 150 on mobile.

A bounded CPU diagnostic identified `VirtualLayoutCommit.componentDidUpdate → restoreVirtualLayout → getBoundingClientRect` as the dominant mobile geometry cost (3.29 seconds accumulated). Every virtual-range render was restoring an anchor even when no physical size changed. The follow-up source change finalizes correction after the parent's measurements, and skips it for unchanged model/size/margin revisions. Pending remounts remain independent. The regression asserts zero post-mutation anchor reads for unchanged-size recycling, while still completing an exact pending remount on that path.

An intermediate development build (`4ae26e2fb18a`) retained all twelve prepend anchors but failed the new real-width reflow check: desktop moved 22 pixels and mobile moved −176 pixels. It was not deployed. `ChatReading.onResize` refreshed the active turn without using the saved position after a reader gesture had released paging ownership. The follow-up restores that saved semantic position only for settled readers, retaining both the pending-input guard and follow policy. Its viewport contract reproduces the missing restore and verifies that pending user scrolling suppresses it.

The second geometry hotspot was ref-time measurement while React was still placing sibling rows. Ref attachment now returns the existing cache/estimate; the parent effect measures the complete DOM before deciding correction, while ResizeObserver continues to handle later changes.

Every prepend retained its exact text offset at 0 pixels. Cached traversal, latest navigation and keyboard behavior passed.
