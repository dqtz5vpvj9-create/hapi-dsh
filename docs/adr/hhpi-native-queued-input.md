# Native queued input remains visible in Conversation

Status: source implemented; candidate browser acceptance and release are separate, pending checks.

When a Codex source accepts `thread/queue/add`, the editor may clear before the agent consumes the message. The official Conversation QueueDock must keep the original text and attachments visible during that interval. A separate queue-management panel does not fulfill this behavior.

HHPI now supplies the official `inbox` projection from an authorized, uncached `thread/queue/list` read. One retained source Session owns the read, coalesces initial admission, source metadata, action-ledger and user/turn-boundary refreshes, and shares the result across Panes. Reads, mounting and reconnecting never dispatch a write. A failed read preserves the last confirmed rows but prevents edits or removal based on an unchecked snapshot.

`clientUserMessageId` links the local submission to the original native queue occurrence; the native queue ID remains the action target. QueueDock deduplicates matching local and source rows. The local submission remains as a fallback when the item leaves the source queue before its body arrives. Source-confirmed text, including another client's edit, updates the displayed row and its handoff fallback. An exact native `user/message.source.rpcId` records consumption; the submitting Pane's official reading-window publication and its assembled Chat node must match the exact native ID, sequence and content before that fallback retires. Source observation alone is insufficient. Explicit accepted removal retires the original occurrence immediately.

When the same retained draft is sent again after an unknown outcome, the native ledger may confirm the original operation instead of dispatching the new local handle. After that immutable payload has been checked, HHPI associates both local handles with the original native client ID and publishes only that ID. Source edits update this one fallback. Removal settles every local alias; body handoff waits for their submitting readers and settles each callback once. Rechecking an aliased handle still addresses the original ledger operation, including after acceptance. A changed draft is never merged with an unresolved original.

DSH `ui-conversation` gains one optional JSON `queueActions` projection, keyed by original queue ID, with `edit`, `remove` and `steer` booleans. A missing projection or row preserves ordinary DSH behavior. HHPI enables Edit when the native source exposes update and Remove when it exposes deletion. The optional `editText` supplies only actual native text to the inline editor; the source preserves image/file, skill, mention and other non-text parts and their order when updating that original item. Missing `editText` retains ordinary DSH text-only editing. Steer is enabled only when the same source advertises the HHPI adapter action `hhpi/queue/steer` in its existing methods map and supplies a current native active turn. The original `turn/steer` method keeps its native semantics; `thread/queue/start` is idle-only and is never substituted for insertion into a running turn. Executors independently check source capability, authorization, current original identity and immutable input before using the original NativeActionOwner. Unknown writes retain their original ledger identity and are never blindly resent.

The empty-input InputBar hint and keyboard action use that same queue capability. If any queued row denies Steer, the queue-wide Steer action is unavailable. InputHub reads current queueActions again immediately before each queue-wide operation, so a callback retained before a capability change cannot dispatch it afterward. Typed draft steering keeps its existing policy and execution path; a missing projection keeps ordinary DSH behavior.

The same native QueueDock keeps a matching local submission's real image/file previews when the source queue lacks durable attachment references. Durable references take precedence. No browser preview becomes a fabricated source attachment, and no extra upload is introduced. A fresh browser can reconstruct source text and action identities from the queue; queued source images without durable refs have an image description until their source body arrives. Local compression and source upload receipt resolution keep their existing owners.

Queue action failures notify the exact retained reading binding's input shell; ordinary Sessions continue using their normal binding.

No Session wire, persisted event format, host projection registry, CSS, or normal DSH default changes. The new DSH declaration is a client projection type read by the existing Session face; HHPI's source adapter provides its value. Tests distinguish fixture RPC, native React component behavior, official reading-window publication and real runtime acceptance. The previous test expecting immediate echo retirement after `accepted` encoded the reported disappearance and has been replaced with continuous native-dock handoff assertions.


The source queue-transfer owner retains the complete exact native item/input/client ID in a private fsynced journal before removal. Only a confirmed native `deleted=true` permits one `turn/steer` with the captured exact turn and original client ID. Native consumption or `deleted=false` never submits the input again. Definite steering rejection permits a separately receipted restoration of the same input/client ID; the restored native queue ID becomes the action target while the original client ID preserves body/attachment correlation. Unknown deletion, steering or restoration causes read-only reconciliation, never a resend. Full retained inputs belong to the source journal, not the browser receipt store.

Receipt absence is distinct from an existing uncertainty marker. After a process stops before deletion, or after confirmed deletion but before the steering step has an attempt marker, read-only restoration exposes the existing native Send-now action as explicit continuation. It follows the original claim and child operation IDs and captured turn, executing only an unattempted step. Page mounting, source queue reads and receipt lookups never resume that write. Source-held rows in actual uncertainty remain visible with native sending/confirmation state and omit misleading inactive actions. Ordinary DSH presentation is unchanged when the optional delivery projection is absent.

The source item lock serializes HHPI-origin queue mutations and transfers. Codex's list/delete API has no compare-and-swap token: an external native client editing between the list check and native deletion is outside that lock. This composition is not a cross-client atomic native transfer, and no such guarantee is claimed.

A retained continuation remains actionable when the captured turn has ended: it uses the captured turn ID, so definite rejection returns the original input through the same source receipt. This does not target a new turn. Ordinary untransferred rows still require a current steerable turn. QueueDock respects explicit per-row source availability; absent projection retains its ordinary running-state default.
