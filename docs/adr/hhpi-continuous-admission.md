# Continuous reading admission

The old opening envelope (5,000 events, 12 MiB and 2,000 derived Contexts) was applied to every cumulative complete-window commit. A reader could therefore load valid pages and then hit an unavoidable `CAPACITY_EXCEEDED`. The old six-page fixture stopped at 1,120 nodes and could not expose that boundary. A new regression fails on the old coordinator at 2,080 nodes.

Complete-window sources now opt into `WindowCommitHostV1.capacityScope(): 'growth'`. The coordinator charges new or revised source entries against the unchanged event/byte envelope. A candidate supplies the actual stable derived Context keys; only keys absent from the last accepted commit consume node admission. Removed identities do not create a permanent charge. A disjoint replacement still admits all its new entries and Contexts. Pending or rejected candidates never become a capacity baseline. Hosts that omit the option retain the original whole-window limits, and a growth host without Context-key evidence retains the absolute node limit.

HHPI applies its event/byte budget to each incoming source page and relevant live revision, rather than trimming the opposite end of already accepted history. The official virtualizer controls mounted rows; logical resident history is not a count of mounted DOM nodes. The source-side 4 MiB event and 8 MiB page limits, authorization, version checks, reader-anchor retention checks and publication transaction remain in force.

Resident history is retained for the reading occurrence's lifetime. The shared cache's 32 MiB/20,000-event targets evict unowned entries, never an active reader's entries. Thus these are soft cache targets while a reader retains more history; this change does not provide a hard process-memory ceiling. Closing an occurrence releases its pins. A future disk-backed retained history would be a separate storage design, not a larger arbitrary reading threshold.

The local replay journal retains at least its latest checkpoint even when the resident snapshot exceeds its byte target. That checkpoint references already resident entries. Expiring it immediately would incorrectly label the current subscriber as stale; only older checkpoints are eligible for eviction at that boundary.

The source transformation is in `scripts/dsh-ext/reader-publication.mjs`, applied to pinned upstream source. It is optional, generic and source-level; the normal upstream path remains unchanged. `tests/contracts/hhpi-official-history.test.ts` reads 40 pages through the real assembler and coordinator, verifies 6,400 continuous bodies, an independent Pane, resident-tail reuse and live revisions, and separately checks rejection by the default bounded-window coordinator. The production provider tests cover cumulative bytes/events, live updates and genuinely oversized page rejection. Browser acceptance must additionally cross the old node ceiling with real geometry; in-process geometry is not that evidence.
