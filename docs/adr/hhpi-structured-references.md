# Opt-in structured composer references

Status: implemented against DSH `0.2.2-rc.1`, commit `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`.

The official reference codec previously returned only model text. That loses the identity of an explicitly selected skill or plugin before an adapter receives the prompt. Encoding an instruction or a private JSON marker inside text would make its interpretation depend on prompt parsing.

The client Session contract now exports `PromptReferencePart` (`type`, `source`, `ref`, and a human-readable `label`) and `SessionPromptContentPart`. The existing Host `PromptContentPart`, Session prompt wire, and HHPI v1 stay unchanged. A codec can still return a string; it may instead return one typed reference. The trigger controller supplies the exact retained binding to codecs as an optional third argument. Official draft serialization preserves references in their original order beside text and formatted quotes. No reference is inferred from quoted text.

A Session opts in through `promptReferences.accepts(namespace)`. ConversationController checks every namespace before registering a submission or touching its attachments. It carries optional `BeginSubmissionInput.content` so an adapter cannot prematurely admit a structured prompt as ordinary text. An ordinary DSH Session rejects a reference before its Host RPC. Existing string codecs keep the same serialized string and submission path. Omitting the opt-in or retaining string codecs independently disables structured submission.

HHPI owns two namespaces: `hhpi:codex:skill` and `hhpi:codex:plugin`. Selection comes from the addressed source's enabled skills and installed, enabled, available plugins. Submission rechecks the selected identity in that source directory. Native inputs are real `skill{name,path}` and `mention{name,path}` values. Plugin paths use the documented `plugin://<name>@<marketplace>` form, never a title search or a hidden text marker. The protocol's skill and explicit mention variants are documented in [Codex's UserInput source](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/user_input.rs); the installed `codex-cli 0.165.0` generated schema supplies this implementation's pinned field check.

Queue submission calls native `thread/queue/add`; steering calls `turn/steer` with the original active turn. Both use one account-scoped NativeActionOwner `composer` intent. The operation ID, native client user-message ID, and native turn/queue result remain separate. An uncertain request keeps its original immutable parameters and can only query its original receipt. Mounting, restoring or reconnecting does not dispatch it. A changed draft cannot replace it. Preflight captures the account/source authorization generation so delayed directory or receipt resolution cannot bind the old draft to a new account.

Images and final native inputs are stored in the existing transactional operation ledger; localStorage contains only small index pointers. Existing uploaded file receipts are resolved by the independent `sourceWorkspace/uploadInputs` service. It accepts only the exact session ID and receipt IDs. The source executes existing `CodexUploads.inputs` checks and returns its real native text/local-image inputs. Gateway authorization is checked before and after this read; native submission is authorized again by the existing native carrier. The browser never derives source paths. An unavailable receipt, unsupported namespace, source revocation or failed preflight retains the editor and attachments.

A temporary echo retires only when source history carries its exact native client ID, including an item already present when the subscription starts. That proof retires the echo but does not forge a native operation receipt. Matching text, settings or other metadata never settles an uncertain receipt.

The source changes are generic and live in `api/session-controller`, `client/ui-conversation`, and `client/ui-input-trigger`. They are compiled from the pinned licensed source and included in the consolidated rc.1 source patch. No compiled JavaScript is edited and no runtime method interception is used. Tests exercise the real official input shell, quote serializer, ConversationController, ordinary Session boundary, HHPI Session, action owner, and source receipt IO; native RPC and upload/network transport are explicit fixtures. Real source execution, browser geometry, a physical keyboard, and deployment remain separate delivery checks.
