# Reuse private preparation without sharing mutable validation

Status: source implementation; candidate integration and desktop 80ms acceptance remain pending. Package: `@deepseek-ai/dsh-client-ui-conversation`, pinned DSH `0.2.2-rc.1`, upstream `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`.

The `.14` formal desktop result remains 100ms against the unchanged 80ms gate; the 390px scene passed at 67ms. A subsequent single desktop CPU trace, with geometry methods unmodified, identifies a 102ms publication microtask with only 1.95ms of style/layout work. Approximately 51ms of CPU samples belong to `buildCandidate` rebuilding an independent assembler over the entire resident window; another 11.65ms belong to live context replay. The earlier prepend fix preserved the published assembler, but preparation still interpreted every old source event again. Trace timings are diagnostic and do not establish a same-input speedup.

Each complete-window coordinator now owns one reusable private assembler. The shared reconciliation method permits incremental growth only when every prior event entry, including retained source dependencies, is present by exact identity. It sends new interior/older entries through the existing prepend/dependency replay and new tail entries through append. Revisions and removals replace the complete private window. A prepend with no fresh entries and unchanged older-history state does not rebuild the location index. Ordinary non-complete-window candidate construction keeps its prior fresh-assembler path.

Prepared tokens retain copied reading-key evidence and derived Context keys, rather than a pointer to this mutable private engine. A later preparation, replacement or discard cannot change an earlier token's validation. The visible assembler remains separate and is changed only inside the existing synchronous measure/publish/correct transaction. No source dependency is omitted and no asynchronous correction, timer, reduced page, synthetic height or new HHPI field is introduced.

Before each private projection is materialized, independently forkable grouping state is seeded from the currently published owner and its private view builders are reset. Discarded work cannot allocate the visible owner's future grouping identities. Registry replacement rebuilds live history views, invalidates the private cache and rejects tokens prepared under the former registry generation. This generation check covers the demonstrated case in which an old prepared callback could otherwise commit after plugin replacement even though its source version had not changed. A failed plugin interpretation retires the partially changed private engine before reuse.

The regressions cover two consecutive body insertions after a dependency prefix, unchanged resident object identity, real revisions/deletions, a later private replacement that must not poison an earlier prepared token, registry replacement and grouped owner preservation. Actual dependency consumers also verify new tail updates, revised dependency events and removal of the source prefix. These use production Conversation/assembler/coordinator code and explicit source-feed fixtures; they do not prove browser performance. The measured Latest click and separate `scrollMetrics` restore/resize chains remain unresolved observations and are outside this change.

Three associated source contract files pass 74 cases (`9b3116e6-ba23-46f6-8deb-eea607179567`). The five changed source/test leaves pass strict scoped types (`3506266a-fb4f-4541-9ad7-4173e4e822de`). The typecheck uses the official ui-conversation project reference graph and CSS declarations; an initial temporary config accidentally reused ui-chat references and redirected the test import to the earlier generated assembler declaration. No declaration or installed package was edited to satisfy the check.

The first `.15` cohort build failed at the official client-bundle purity gate because the new registry rejection imports the shared `WindowCommitError` value without declaring its module-table request. The correction adds `@deepseek-ai/dsh-api-session-controller/client` to ui-conversation's existing `dsh.client.external` mechanism. The purity gate stays unchanged, and the constructor stays in the controller module so its `instanceof` handling preserves `STALE_VERSION`. A real package bundle passes (`0823ce94-170f-4e61-850f-9a862339b4f0`); its emitted client requests that module and calls the shared constructor without an inline class copy. The failed `.15` source inputs remain preserved. This correction will enter the next cohort alongside the independently verified workspace restore change; no candidate or performance result has changed yet.
