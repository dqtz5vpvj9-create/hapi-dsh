# Resource-owned browser terminals

HHPI source workspaces need user shells on the machine that owns their files. A Codex-only workspace has no DSH execution Agent. The DSH `0.2.2-rc.1` terminal service obtains its process provider, working directory and cleanup lifetime from `Agent.ctx`, so its public Remote class cannot be used directly for this source owner.

The source extension exports `createTerminalOwner(scope, spec, config)` from `@deepseek-ai/dsh-api-terminal-controller`. The spec carries the original Session address, a real source subprocess provider and directory read/validation callbacks. The supplied Cordis scope owns the resources. One returned controller survives Pane and connection lifetimes; explicit disposal and scope teardown share process cleanup. The original Agent Remote facade uses the same owner implementation and retains its provider checks, working-directory recovery, namespace and configuration.

The factory manages the existing PTY, bounded screen, retention, pending allocations, closed identities, ordered input and provider acknowledgements. `attach` takes the current physical stream's decoded uplink, cancellation and optional encoded-frame input window. It does not replay input or create a replacement process. No internal BrowserTerminal class is published, and no fake Agent or Agent.ctx is constructed.

User terminals run with the actual source system user's permissions, independently of Agent sandbox mode and approval policy. Source OS/container restrictions and the subprocess provider's credential-environment scrub remain effective. The factory neither registers a Remote endpoint nor grants source access. The source-workspace service must use existing Gateway authentication, enforce current account/source/session/workspace grants and end revoked streams. The official Agent-addressed terminal Remote cannot resolve a Codex-only source owner; that integration uses the separately authorized workspace service and the public official client model.

The patch changes only the terminal-controller package and its development-only workspace lock entry. `owner.ts` is explicitly included in its Host TypeScript project. A development dependency on `dsh-app-boot` lets a real `cordis.yml` composition exercise a source owner and the native subprocess provider without loading Agent services. The package's English/Chinese README and pairing record describe the public API. No Session format, HHPI v1 method, terminal frame or error changes are required.

The extension can remain unused: ordinary DSH continues through the original Remote facade, and an unregistered source-workspace terminal provider exposes no source terminal capability. Unloading an actual owner cleans up its owned processes; closing a Pane only releases a view. If an owner restart loses the original process, restored clients report the missing terminal and must not launch another shell as recovery.

Focused validation covers the original controller and client recovery behavior, explicit owners without Agent services, independent owners, pending create/close races, cleanup failure/retry, input-window propagation and a real app/Loader composition. The latter writes a file in an isolated source workspace, reconnects to the same shell PID and observes process termination after explicit close. Source-service authorization, browser integration, phone controls and the final installed Host/Runner set remain separate integration checks. Execution results and any build/install failures are recorded in the T1 delivery evidence rather than inferred from these API guarantees.

The source patch is archived against commit `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db` through the existing `source-snapshots/dsh-ext/source.patch` pipeline. The `0.2.1-rc.3` patch history is preserved. The release source offer includes this decision and the [upstream draft](../upstream-pr-dsh-terminal-owner.md); pushing it to the third-party upstream is outside this change.
