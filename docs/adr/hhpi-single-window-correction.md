# Keep one measured correction during a history publication

Status: source implementation and scoped contracts complete; installed performance acceptance pending. Upstream DSH `0.2.2-rc.1`, commit `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`.

The `.9` desktop failed the unchanged 80 ms frame budget with a 150 ms gap. Its largest 165.7 ms microtask contains three style/layout passes, totaling 51.3 ms of style and 49.6 ms of layout. The first virtual-list pass retains all fifteen rows; the next mounts six new rows before the final viewport correction. A bounded, read-only browser diagnostic additionally observes a component-owned `marginTop` change causing a fresh border-box measurement without any body change.

The coordinator already exposes `inCommitCriticalSection` around measurement, synchronous publication and reader correction, with cleanup in `finally`. Conversation now offers an optional per-window `isCommitting(viewId)` read and Chat forwards it as optional `isCommitting()`. Chat updates its current source facts during publication but leaves automatic content/resize reconciliation to the measured correction. Previously `contentCommitted()` called `preserve()` inside the publication, releasing the virtualizer's retained range before the coordinator applied its own correction. Explicit navigation remains on its original path. Without the optional read, the default path is unchanged; no timer, animation frame, additional publish or delay is introduced.

Virtual rows also exclude their own outer `marginTop` mutation from body-height invalidation. The gap is already added separately to the accepted border-box height. Actual body mutations, inner styles, hidden state, new DOM seats and resize observations retain their measurement behavior.

The real Chat scroll hook regression first fails by observing an early `scrollTop = 600` write during publication, then passes with only the coordinator's correction writing that position. Conversation contracts check the read during measurement/correction, per-window isolation, release and correction failure. Virtual-row contracts check gap-only reuse and true content changes. Browser geometry, continuous reading, cache reuse and the 80 ms requirement remain separate acceptance checks; the source tests do not supersede the `.9` failure.

The `.10` full desktop still fails at 133 ms. A subsequent native trace attributes 62.1 ms in one 100 ms frame to two `VirtualChatRows` layout effects; another frame includes a 26.4 ms `rowsCommitted` microtask that preserves an anchor already corrected by the coordinator. A separate bounded mutation diagnostic observes retained disclosure rows remeasured solely because `data-turn-process-messages` and `data-turn-process-tool-calls` changed as older members arrived, followed by legitimate measurements of newly mounted neighbours. These observations do not establish a browser improvement.

The follow-up avoids queuing that second automatic preserve when an already opened reader reports rows inside the coordinated publish. A first reader still queues its initialization, and later body/image resizes keep their own preserve path. Virtual-row invalidation also excludes the three source-count attributes owned by `TurnProcessNodeView`; they are metadata, with no text or style consumer. The exclusion is limited to that component's count attributes. Text, child, style, hidden/expanded state, new mounts and resize measurements remain authoritative. Regression contracts first reproduce the extra geometry reads, then check their removal and subsequent real growth. No timeout, reduced range, geometry estimate or changed acceptance threshold is introduced.
