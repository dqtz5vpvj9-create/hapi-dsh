## 连续触摸发现了此前漏掉的失败

原触摸实现自动点击官方补页按钮时会保留旧锚点，长拖 430px 却只移动约 14px。等真实外层滚动结束再触发自动补页后，对照样本移动约 415px；抬手和 `pointercancel` 都不再直接代表滚动结束。自有阅读恢复也让出持触和惯性阶段，明确导航仍保留优先级。

随后，最终 7 项冷启动与触摸专项中仍有 360px 一项失败。最初显示 4 帧无可见正文；五个视口局部命中点证明这四帧有真实正文，是 IntersectionObserver 尚未交付。测量修正保留 `blankFrames=0` 门槛，并单独记录交付盲窗。

继续测量上一帧的同一个 DOM 锚后，发现另一项真实问题：在途分页遇新手势时，旧消息仍连接，却突然移位约 1840px；混入同帧手指位移后达到 1903px。此前只比较两帧共同可见的节点，整页换位后没有共同节点，因而漏报。新增保留锚断言后，360px 正确红灯，不以静态截图或其余通过项覆盖该失败。

- 红灯日志：`/mnt/cache/data-cache/hapi-touch-360-retained-anchor-red.log`。
- 帧证据：`/mnt/cache/data-cache/hapi-dsh-visual-review/touch-360-1792774063478.json`。
- 保留门槛：主动触摸单次保留锚位移小于 160px；静止补页仍要求不超过 1px。
- 新增并发场景：旧分页在第二次真实甩动的惯性阶段到达。旧产品的该场景通过，因此修复也必须保留页面继续惯性移动，不能用停止惯性换取位置稳定。

第一版持触补偿在共享 Host 的 360px 场景将旧锚位移从 1903px 降至 63px，持触停顿后继续拖动、在途页与惯性交错也通过；但同轮最大帧间隔 216.6ms 仍超标。随后独立启动的 360px 场景又出现 1840px 跳跃和 216.7ms 帧间隔，当时手指仍按住而补偿标记没有生效。这两次失败保留在 `hapi-touch-candidate-directed.log` 和 `touch-360-1792775587202.json`，不能由后来偶然通过的一轮覆盖。

事件诊断增加了可信触点目标、补偿标记装卸、外层/嵌套 `scrollend` 与分页结案时间。Long Animation Frame 记录中，225.7ms 那帧仅有 34.8ms 脚本、强制布局为 0，另有多帧没有脚本条目；目前不能把超时归因于新增单锚补偿，也不能归为环境噪声。测量脚本不保存消息正文或凭据。

后续事件轨迹确认了两处独立原因，并分别补了回归：

1. 手势从工具过程按钮开始时，原逻辑将其排除在补页保护之外。按钮可以成为原生拖动起点；修正后仍排除真正的编辑器和能消费该方向的嵌套滚动区，保留按钮点击功能。固定近顶场景的保留锚位移从 1840px 降为 0，手指继续拖动时总移动由 91px 增至 331px。证据为 `touch-inflight-process-button-1792776482961.json`（失败）和 `touch-inflight-process-button-1792776682706.json`（修正后）。
2. 实时尾部合并将节点数从 148 变成 147，最早节点身份和 DOM 都未变，却被当成整个历史窗口替换，提前释放了保护。现在必须同时观察到节点数减少和最早节点身份改变。独立 360px 回归 `touch-360-1792777249384.json` 中双向各移动 1448px，保留锚最大位移为 0/62px，反向回拉和空白均为 0；62px 属于手指实际移动。

随后全套 8 项触摸与 2 项冷启动验证为 **9 通过、1 失败**，日志 `hapi-mobile-cold-final-ten.log`。所有补页与位置断言通过，但展开工具输出后向较新消息滑动测到 216.6ms 帧间隔，仍超过 200.2ms 门槛。单独诊断 trace `touch-scheduling-1792777475114.json` 观察到手势中可选插件下载完成后的同步 React 更新，单次加载回调为 76–129ms；这提供了待修的实际工作来源，但不证明它独自解释此前每次超时。后续工作不能用这次诊断未复现 216ms 替代失败记录。

## 顶端加载期间连续滑动的追加修正

用户补充的精确触发条件是：更早历史正在加载，读者已经到达顶端，仍继续向更早滑动。为此仅恢复这一项修复，保留前述停止范围。

`2a044ef` 的固定负对照复现了整页跳跃：第二个可信手势从顶端禁用的加载按钮开始，实际位置始终为 0，因而没有产生新的 `scrollend`。该手势的 `touchstart` 使官方分页锚释放，而自有保护又在 `touchend` 和 180ms 收尾时撤掉。抬手后等待 250ms，再放行此前阻塞的历史请求，同一个旧首条 DOM 的视口位置由 46px 变成 1886px，滚动位置仍为 0；新增内容恰为 1840px。失败日志为 `hapi-earliest-boundary-2a044ef-gap-red.log`，原始记录为 `touch-earliest-released-gap-1792799585574.json`。

修正只对“自有补页仍在途、向更早意图、滚动位置仍为顶端”的抬手间隙保留单个锚记录，并移除自有 CSS 标记，让浏览器继续处理原生锚定。补页到达时只补偿仍停在顶端的未处理位移；浏览器或读者已经离开顶端则不再写入位置。普通惯性、新手势、窗口替换、隐藏和失败仍沿原有路径释放保护，没有修改官方 DSH。

修正后的五项定向官方浏览器用例通过，耗时 53.7s。新增持触、抬手间隙两项均实际插入 1840px；旧首条 DOM 的视口位置保持 46px，滚动位置从 0 补到 1840px，空白与反向回拉为 0。另三项保留长拖、实际惯性以及从工具按钮开始滑动的行为。日志为 `hapi-earliest-boundary-candidate-five.log`，新场景记录为 `touch-earliest-held-1792799784964.json` 和 `touch-earliest-released-gap-1792799794223.json`，均位于本机临时证据目录。

另补了一项“旧分页在下一次手势的真实惯性中返回”的回归，也通过：补页后仍继续惯性滚动 678px，保留锚最大步进 68px，空白和反向回拉为 0，最大帧间隔 116.7ms。该轮 14 秒，日志为 `hapi-earliest-boundary-inflight-fling.log`，原始记录为 `touch-inflight-fling-1792799870657.json`。因此本次定向浏览器验证共六项通过，没有重跑无关的安装、冷启动或完整性能套件。
