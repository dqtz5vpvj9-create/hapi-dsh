# HHPI 远程接入架构

状态：目标方案，尚未完成实现。现有包名与技术标识仍为 `hapi-dsh`；本次澄清不触发包、配置、数据目录或接口重命名。V4 当前实现见 [源消息窗口](source-view-architecture.md)，当前阅读问题及验收边界见 [连续历史设计](continuous-history-design.md)。

## 产品定位

HHPI 是供 DSH Web 使用的通用 Agent 远程接入插件，为 DSH、Codex 及其他 Agent 提供类似 HAPI 的跨机器访问能力。HAPI 是参考实现，可复用、修改或替换其相关代码；HHPI 不需要复制其消息格式、Hub/Runner 划分或内部架构。

唯一目标前端是 DSH Web。无需同时维护 HAPI Web，不以两个 Web 共用数据模型作为设计前提，也不为 HAPI Web 兼容性保留多余转换。现有 HAPI 来源可作为迁移期间的适配器存在，不作为所有 Agent 的必经层。

## 目标链路

```text
DSH Web：Conversation、编辑器、插件视图与同一官方读者
  ↕ HHPI 的会话目录、读取接入与操作路由
HHPI：认证、连接、订阅恢复、取消、资源作用域
  ├─ DSH 接入：源 Host 的原生 DSH API 与事件
  ├─ Codex 接入：源机器 app-server 与历史读取适配器
  └─ 其他 Agent 接入：该引擎的原生协议适配器
```

上述是职责划分，不要求每一层部署为独立进程。远端需要主动反向连接时，可参考现有 Runner 实现；Hub 与 Runner 的具体拆分服从部署需求。

## 通用性放在哪一层

HHPI 统一机器配对与撤销、连接状态、会话发现、请求路由、订阅恢复、取消和资源授权。源会话由机器、引擎和原会话身份共同定位；不同机器上的同名会话或相同原始 ID 不得互相覆盖。

引擎适配器提供会话目录、历史与实时读取、能力声明，以及该引擎实际支持的发送、Steer、取消、审批等操作。不支持的能力明确缺省；HHPI 不通过伪造本地执行状态补齐它们。命令结果不确定时保留该状态，不自动重发可能已执行的写操作。

文件、附件、终端和其他插件资源沿同一源作用域路由。插件需要源适配时明确提供适配，不因聊天可以显示就宣称所有插件都能跨机器运行。

原生执行、审批与队列继续归源引擎。关闭 Pane 仅释放读者与订阅；协议窗口更换、断线重连或历史回退都不创建另一个执行 Agent。

## 两种来源，避免重复转换

### 原生 DSH

优先转发源 DSH 已有的 API、事件和插件能力。传输可携带机器路由与请求关联信息，但不把 DSH 消息先改成 HAPI 消息，再重新生成 DSH 事件。

DSH Web 消费原协议，保留原 Session、事件顺序与操作归属。现有跨 Host 接入是应核查与复用的起点；协议透传是否成立，以实际代码和端到端行为确认，不能仅凭接口名称判断。

### Codex 与其他非 DSH Agent

适配发生在最接近源引擎的位置。适配器直接读取原生历史与更新，提供稳定消息/内容块、原生关联、源顺序、完成状态及版本。历史和实时沿用相同身份；分页只读取或切片，不能从开头重放全部历史。

这条路径不必先构造 HAPI 的角色封装，再经过 Host DSH projector、SourceFrame 编码、客户端 seq/turn/step 重映射和执行生命周期组装。浏览器只保留必要的消息到展示节点适配，不再为正文建立第二套执行运行时。

读取模型是可重建的投影，原生记录仍是事实依据。正文可留在源机器，按需读取；不要求复制完整 transcript 到中央服务。源协议需要补充历史索引或稳定引用时，可直接修改相应适配器与本机 HAPI 相关实现。

## DSH Web 的输入边界

保留官方 Conversation、Chat 展示组件、编辑器、虚拟列表与读者。原生 DSH 沿现有事件路径进入；非 DSH 来源需要完整的消息展示数据源接入，不能只替换 `useChat`，却让导航、详情和历史操作继续读取另一套 assembler 状态。

当前 `HistorySnapshotV1.entries` 接受 `SessionEventLikeEntry`，`ChatSnapshot` 又包含实时读取器和对象引用，均不能直接当作通用消息网络协议。Chat 的 `anchorSeq`、turn/step、timeline 与 legacy slice 也仍有事件假设。

先以接入原型确认现有受支持注入点能否一起提供节点、顺序、导航与提交。接口不足时，按已有 DSH 补丁授权增加可选、通用的数据源入口，原生 DSH 默认路径不变，并保留 ADR、契约与上游 PR 草稿。需要的改动范围由原型核实，不预先承诺零修改或“小补丁”。

若选择由非 DSH 适配器生成官方 DSH 事件，身份和顺序也必须由源端一次确定，直接交给 DSH Web；不得再经 SourceFrame 往返和客户端重新编号。这是有生命周期耦合的兼容路线，不能与直接消息接入混为一条路径。

## 连续阅读的归属

- 客户端共享已接受的消息条目，每个 Pane 只拥有自己的一个连续窗口、导航与取消状态。共享数据不等于共享“当前看哪一页”。稳定源身份与页游标分别表达身份和位置，不以大整数基数、固定步长或加载顺序替代。
- 历史与实时变化连接在明确版本上，重连补齐版本后的变化。真正的历史改写撤销旧游标与在途响应；普通补页和正文修订不制造断线恢复。
- 自动上翻与按钮调用同一个导航入口。候选窗口准备完成后，由同一官方读者在发布前采样当前锚点、发布一次、在布局后恢复；请求期间的新滚动以提交时的阅读位置为准。
- 版本连续且预算允许时，回到已读区间直接使用已有内容。只有真实预算压力才释放消息，并保留可回读边界；DOM 虚拟范围不决定正文缓存范围。
- 请求直到发布和布局恢复结束才完成。失败保留旧正文与明确错误状态，避免 busy 清除后立刻自动重拉造成“加载中”反复闪烁。

## 落地顺序与删除范围

1. 分别画清原生 DSH 和 Codex 当前接入路径，确认每项身份、正文窗口、游标与操作的唯一 owner；首先移除不必要的 DSH → HAPI → DSH 往返。
2. 为 Codex 做一个不依赖 HAPI 消息封装的源端读取适配原型，并接入真实 DSH Chat 组件。覆盖跨页工具、流式完成、内容修订和请求期间滚动，明确数据源接口需要的 DSH 改动。
3. 接通共享条目缓存、每 Pane 窗口、唯一导航与提交者。保留源执行及已有安全边界，再对实际长会话验收。
4. 切换后，从非 DSH 正文路径删除逐页 DSH projector、SourceFrame 编解码、SourceWindowStore 坐标重映射及 SourceEventFeed 桥。SourceRecord 中正文与分页职责退出，操作桥按实际需要保留；调用清零后才删文件。
5. 当前 HAPI 来源适配器按迁移需要保留或退役。无需等 HAPI Web 切换，也不为双 Web 共用模型新增兼容层。切换后每个来源只走一条正文路径。

## 验收

原生 DSH 与 Codex 分别使用真实长会话，在桌面和手机视口连续六段上翻；第二、第三次及后续均须实际出现更早正文。往返锚点稳定，预算内已读区间不重新取页，实时追加不打断阅读，双 Pane 保留独立位置。

可控请求覆盖慢页、失败、迟到响应与重连，确认旧正文一直可读且旧响应不覆盖新导航。发送、Steer、取消与审批仅在合成会话验证源目标和结果归属。原始数据页计数、游标推进、截图、构建和发布成功均不能代替阅读结果；执行方法遵守 [测试说明](testing.md)。

## 现有代码的参考价值

- `hapi-dsh` 的配对、远端 DSH Runner、跨 Host provider 与资源作用域：可复用的接入基础，仍需逐项核对语义。
- HAPI 的连接恢复、原生引擎桥、历史索引和消息窗口：可参考或抽取，不要求照搬整条链路。
- `hapi-dsh/src/shared/source-frames.ts` 与 `src/client/source-window-store.ts`：当前身份往返、跨页坐标和引用回填的迁移对象。
- `dsh-ext/packages/client/ui-chat` 与 `packages/client/ui-conversation`：应复用的展示与阅读能力，以及需验证的数据输入边界。
