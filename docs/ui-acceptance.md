# HAPI-DSH UI 与性能验收

用户已将 UI 验收交给 Agent。本流程替代此前“上线后交给用户手测”的阶段规则。原始目标见 HAPI 的 `docs/chat-experience-contract.md` 和 `docs/plans/tmux-workspace-implementation.md`：首次打开、双向历史滚动、实时更新、输入、多 Pane 和手机操作均须覆盖。

## 快速运行

首次完整构建后，启动一个常驻环境：

```sh
TMPDIR=/mnt/cache/data-cache npm run build
TMPDIR=/mnt/cache/data-cache npm run e2e:warm -- serve
```

迭代时运行 `npm run e2e:warm -- rebuild-client`，然后 `npm run test:ui`。报告含逐项结果、原始帧间隔、长任务、锚点漂移、正文/输入框可用时间、DOM 与堆数据。失败退出码为 1，完整 JSON 写入 `/mnt/cache/data-cache/hapi-dsh-warm-*/`；控制端不输出 admission 凭据。

首开不加载语音 SDK 和长图导出库。两者通过 pinned DSH 的 `require.async()` 包内分块接口在使用时加载；快速验收会打开语音面板并实际导出 PNG，检查分块请求和下载内容。分析主包体积可运行 `HAPI_DSH_BUNDLE_REPORT=/mnt/cache/data-cache/hapi-bundle.json npm run build:client`，得到 esbuild 的模块体积报告。

`npm run test:perf` 连续执行五轮桌面流程，再做 360/390px 手机模拟。Host 和 Chromium 进程复用，每轮清理浏览器 context 并重置合成布局；测试 fixture 的源历史和 Host 缓存保持，所以首轮与后续轮分别报告。Host 启动只等源目录就绪，不预先挂载测试会话；首轮点击包含真实的首次源挂载。打开计时只接受目标标题对应的 pane，不能把切换前的旧输入框计作新会话就绪。验收主体可重新加载，修改 Host/fixture 或导入的采样模块后须停止并重新启动常驻环境。只在客户端变动时重建客户端，避免安装 profile 和启动 Host 的重复开销。

首屏采用较小历史窗口后，静止补页测试先通过官方按钮建立可滚动窗口，再固定阅读锚点并请求下一页；连续双向滚动另行使用真实 wheel 手势。不能在记录静止锚点后滚动 120px，再把这 120px 当成补页漂移。语音与导出分块使用资源观察器记录，避免长流程超过浏览器默认资源计时缓冲区后漏报。

性能运行期间不并行执行构建、其他浏览器测试或 CPU 分析。性能失败保留，不通过重试挑选最好的一轮覆盖。采样器运行在浏览器内，打开计时从正常 sidebar 点击开始，分别等真实正文和可编辑输入框；外部 Playwright 等待不算打开耗时。

完整导航另行计时：恢复测试从 `navigationStart` 到保存会话的真实正文和可编辑输入框，保留草稿断言。`npm run test:perf:production` 使用本机配置的 admission 文件，只读探测线上初次导航及带浏览器缓存的再次导航，输出工作区、正文、编辑器、资源耗时和主线程长任务。`HAPI_DSH_CPU_RATE=4 HAPI_DSH_PROBE_RUNS=1 npm run test:perf:production` 可增加 CPU 降速样本；这是模拟环境，不是真机测量。不得用 workspace ready、骨架或热切换数据替代这个完整耗时。

弱网导航使用 `HAPI_DSH_LATENCY_MS=150 HAPI_DSH_DOWNLOAD_MBPS=1.6 HAPI_DSH_UPLOAD_MBPS=0.75 npm run test:perf:production`。这些是 CDP 的 HTTP 整形参数，不能冒充用户实际线路或 WebSocket 的端到端限速。报告区分 HTTP 编码/解码字节、WebSocket 解码字节、压缩协商、资源完成时间和首屏三个里程碑。探针对 RPC 使用只读许可表，阻止页面自动新建 Session 或保存布局，记录被阻止的路径和次数；不会用假成功回包掩盖这些行为。

冷启动还必须验证内容新鲜度，不能把旧正文当作打开完成。运行 `TMPDIR=/mnt/cache/data-cache npx playwright test e2e/native-cold-opening.spec.ts --workers=1`：保留旧浏览器布局和源历史缓存、重启隔离的官方 Host，再分别阻塞元数据、最新页和完整归档。最新正文与可用输入框必须在归档被阻塞时出现；放行归档后继续逐帧观察，已知标题不得退回占位名或内部 ID，已出现的最新正文不得消失。测试分别覆盖 Native Codex 与 observed Claude 的 390px 和 1440px，归档放行后观察至少 5 秒，并用负对照证明最终恢复正常也不能掩盖中途退化。该测试操作合成源，不能称为生产网络验收。

两类生产打开探针现在均须提供从源端独立取得的 `HAPI_DSH_EXPECTED_TITLE` 和 `HAPI_DSH_EXPECTED_TEXT`；后者应是当前视口应出现的最新正文片段。缺少任一项时，新鲜度或标题身份标为未验证，不能报打开验收通过。采样从应用初始化前开始，首次成功后仍观察至少 5 秒；可用 `HAPI_DSH_OBSERVE_MS` 延长。探针只读，不自动物化尚未建立的源显示会话；被此限制挡住时须如实报告。实现、旧版失败与测量边界见 [冷打开新鲜度](cold-opening-freshness.md)。

`TMPDIR=/mnt/cache/data-cache npx playwright test e2e/cold-boot.spec.ts` 专门验证首屏依赖：阅读期间账户包与 HMR 请求必须为零，真实正文和草稿仍可使用；通过原生入口打开 Settings 才请求账户包。下载期间关闭设置时只缓存资源，重新打开才激活，官方完整插件图必须无加载失败，原输入框节点和草稿保持不变。此用例同时检查浏览器使用压缩载体。另一用例不用 Playwright 路由拦截（它会关闭浏览器 HTTP 缓存），实际导航两次，要求官方带版本名的入口/vendor 脚本第二次传输字节为 0。传输层测试另外覆盖原始帧的顺序、二进制、心跳、重连关闭码及凭据/Origin 拒绝。

远端 DSH 会话必须另测：`TMPDIR=/mnt/cache/data-cache npx playwright test e2e/federated-cold-boot.spec.ts` 启动真实官方 Hub 与配对 Runner，在冷浏览器恢复远端会话；要求首次正文与输入框不请求远端 Account/HMR，刷新后的远端插件传输字节为 0，草稿保留，每次连接只请求一次远端目录。另一用例用超过 20 条消息的远端会话，检查首次 follow 的窗口为 20、向前连续滚轮能通过官方分页找回最早消息、断线重连恢复官方完整窗口请求，以及草稿和重连后的实时消息仍保留。远端设置仍通过自身 Host 的认证传输加载完整插件图。不得用本地 HAPI 源会话或已启动的远端图热切换代替这个用例。

生产远端探针：设置 `HAPI_DSH_PROBE_SESSION` 为既有 `hapi-remote:` 资源标识，运行 `HAPI_DSH_LATENCY_MS=120 HAPI_DSH_DOWNLOAD_MBPS=10 npm run test:perf:federated`。标识只在进程内用于选中目标，报告不记录它。探针在隔离浏览器内提供临时布局，HTTP 只放行列举的读取 RPC，WebSocket 只放行 `session/follow`、`session/control`、`workspace/follow` 与 `$events`（rc.3 的 `session/control` 仅发送状态快照和更新，不接收操作）；其余操作拒绝，不修改源会话或生产布局。原始时序、传输字节和长任务写入 `/mnt/cache/data-cache/hapi-dsh-federated-cold/report.json`。其网络参数只整形 HTTP；WebSocket 经过只读过滤，不能将结果称为用户线路或未经探针干预的精确端到端性能。

队列与命令呈现回归可单独运行 `TMPDIR=/mnt/cache/data-cache npx playwright test e2e/source-presentation.spec.ts`。两个用例共用一个官方 Host，使用与生产字段一致的合成源记录：五条 `indeterminate` 回执只在现有 `⋯ → 会话状态与回执` 中查询，不显示独立感叹号；检查后源端仍未确认时须给出反馈，刷新不重发，真实排队消息仍可取回编辑。带 `command_actions` 的 shell 调用显示简短标题，展开保留命令、输出和真实退出码。覆盖桌面、390px 和 360px，并检查展开菜单的左右边界。固定 webshot 命令输出菜单关闭、展开及检查结果的截图；需实际查看产物后才能报告视觉通过。

手机导航与栏位专项运行 `TMPDIR=/mnt/cache/data-cache npx playwright test e2e/mobile-chrome.spec.ts`。用例使用 pinned 官方 DSH Host、Conversation 和合成源会话，在 360/390px 触摸模拟下检查返回列表、草稿与 pane 身份保留、分屏切换和状态入口，并用 1440px 桌面检查独立标题栏仍然可用。截图由固定 `webshot` 命令重放对应状态；Agent 必须逐图打开并查看，才能报告视觉通过。该专项不发送真实消息，也未覆盖物理手机；命令和断言的存在不代表本轮已经通过。

## 门槛与来源

内存独立验证见 [内存分析](memory-breakdown.md)。`HAPI_DSH_PROBE_MEMORY=1 npm run test:perf:federated` 在打开计时结束后另采自然状态和 GC 后的 JS、backing storage、DOM 与监听器数据，普通性能运行不执行 GC。源流式留存回归运行 `node --import tsx --test tests/source-stream-retention.test.ts`，包含旧切片机制的负对照和真实两种 projector，不用一次短导航代替长期内存验收。

| 项目 | 判定 |
| --- | --- |
| 静止补页锚点 | 每个采样帧偏移 ≤1 CSS px，原锚点不丢失；来自 HAPI 约定 |
| 已读区域往返 | 新的历史页请求和源历史读取均为 0 |

## 手机栏位与导航约定

手机会话顶部不显示 pane 标题栏，也不保留占位高度；桌面仍保留每个 pane 的独立标题栏。一个 pane 时不显示 `P1` 切换条，分屏后才显示 `P1`、`P2` 等入口，并标明当前 pane。

底栏最左侧保留“返回会话列表”（`Back to conversations`）按钮。它打开现有会话选择器，保留当前 pane、会话身份和输入草稿；返回同一会话时不能重建或清空它们。打开列表不自动聚焦搜索框，避免仅查看会话列表就触发软键盘。模拟测试检查焦点归属，实体手机软键盘的实际弹出行为仍须单独验收。

源连接、投递恢复等信息通过现有 `⋯ → 会话状态与回执` 查询，不另设常驻感叹号。手机使用底栏菜单，跟随当前 pane 切换；桌面使用对应 pane 标题栏的菜单。入口不能留在手机已隐藏的标题栏，也不能显示另一 pane 的恢复操作。显式定位回执须同时展开外层菜单和内层回执。未确认的记录保留源端真实状态，不能因为空闲、刷新或隐藏入口而被当作成功、重发或丢弃。正文、输入框、底栏与展开菜单不得横向溢出或相互遮挡。

## 连续触摸与视觉复查

运行 `TMPDIR=/mnt/cache/data-cache npm run test:ui:touch`。用例共用官方 Host 和 Chromium；建立初始阅读位置后，被测操作使用 CDP 可信触摸事件。360/390px 分别连续向较早、较新消息滑动，交替快慢速度；补页分别延迟 80ms 和 600ms，同时发送合成源增量。另一个用例打开长工具过程和命令输出再连续往返；触点固定于外层正文边缘，确认没有落入嵌套输出滚动区，并要求历史增长到至少 1260 个锚。逐帧检查可见锚点是否反向位移、是否空白、手机标题栏是否保持隐藏、输入区是否移动、帧间隔是否超标，另查补页确实发生且没有并发重复请求、草稿没有丢失。

两项专项回归检查自动补页与手势的竞争：手指在一次长拖中静止 650ms 后继续移动，正文仍须随手移动；快速甩动则必须实际记录多帧 `touchend` 后的位移，再检查自动补页发生于外层 `scrollend` 之后。固定等待几百毫秒不算覆盖惯性。首次诊断中，旧实现面对 430px 拖动只移动了约 14px；修复后该次对照移动约 415px。连续变换方向时，以新方向首个可信 touchmove 标记方向归属；此前仍在运行的旧惯性不算新方向的反向回拉。所有帧仍参与最大位移、保留锚、空白和帧间隔检查，不通过等待惯性结束规避连续手势。短时 Chromium 惯性样本不代表物理手机的长甩行为。源窗口替换在手势中的阅读恢复，另由 `tests/client-source-reading.test.ts` 执行真实 binding、以 DOM/Session 边界夹具验证。

手机结构验收同时检查实际生效的根页面/正文 overscroll 边界，分别应为 `none` / `contain`，保留原生缩放与触摸。无头 Chromium 没有 Android Chrome 的刷新提示 UI，CSS 检查不能称为物理 Chrome 下拉刷新验收。

采样器通过 IntersectionObserver 维护可见节点，并用视口内五个局部命中点补足观察器尚未交付的帧；报告单独记录这类交付盲窗，不能把它直接判成正文空白。禁止为测量滚动而逐帧遍历全部历史节点并读取尺寸；这样会迫使屏幕外内容参与布局，使探针自身制造卡顿。触摸性能测试默认关闭 Playwright 的全 DOM 快照，保留操作和网络 trace；需要取证时设置 `HAPI_DSH_TOUCH_SNAPSHOTS=1`。快照会读取屏幕外元素的滚动属性并强制布局，不能与局部采样混为无干扰测量。关闭快照后的失败仍必须诊断，不能直接归为探针噪声。原始帧和汇总写入 `/mnt/cache/data-cache/hapi-dsh-visual-review/touch-*.json`，并附在 Playwright 结果中。

补页还有一条独立断言：继续测量上一帧的单个可见锚，即使它下一帧被推出视口。只比较两帧共同可见的消息会漏掉整页跳跃。本轮在 600ms 延迟分页与新手势交错时，旧节点仍连接却跳了约 1840px；原先的反向位移和空白指标都未报错，新增 `retainedAnchorStep < 160px` 后才正确失败。160px 是主动手势的异常大位移门槛，静止补页仍使用更严格的 1px 门槛。

顶端加载中的连续手势另有两项固定回归：先通过真实触摸到达 `scrollTop=0`，保持更早分页在途，再从禁用的加载按钮开始向更早拖动。分别在手指仍按住、以及抬手后等待 250ms 的间隙放行该页。后者必须超过 180ms 的手势收尾时间，不能用“曾经发生过 scrollend”替代当前顶端手势的覆盖。固定保留同一个旧首条 DOM，证明新内容确实插入了至少 1000px，并要求其视口位置漂移不超过 2px、滚动补偿与文档坐标增量相等、空白帧为零。事件必须来自可信触摸，不合成 `scrollend`。`2a044ef` 的抬手间隙负对照出现 1840px 整页跳跃，这两项用于防止同类遗漏。

手动入口另用真实点击官方更早按钮发起请求，再执行相同的顶端连续触摸；`c5af894` 在此路径也出现过 1840px 跳跃。还须覆盖补页仍在途时从顶端反向滑向较新内容，再放行旧页，要求同一旧行的视口位置保留，不回写先前顶端位置。手动路径必须没有自动 `requested` 事件；配额比较使用同次 `observed/upstream-page` 与 `committed/observed-page` 的 `sessionPages`，不能用可能早于初始预取完成的事件充当基线。

桌面滚轮必须单独验证，手机触摸通过不能代替它：运行 `TMPDIR=/mnt/cache/data-cache npx playwright test e2e/desktop-history-scroll.spec.ts`。三条路径分别是自动补页后继续向上滚、手动加载后继续向上滚，以及手动加载期间反向滚动。真实 Chromium 在 1440×900 视口接受可信 `mouse.wheel`，每次 45–80px；分页设置 600ms 延迟和显式放行门。断言保留同一条旧 DOM 行，新页实际增加超过 1000px，旧行视口漂移不超过 2px，滚动补偿等于新增文档高度。从放行前的稳定位置到提交后的逐帧采样也必须满足同一漂移门槛，不能先跳页再恢复。手动路径不得另发自动分页请求。

`5784b23` 客户端的负对照中，自动和手动继续上滚均将旧行从视口内 46px 推到 1662px，`scrollTop` 仍为 0；反向滚动原本通过。原因是滚轮释放了官方分页锚点，而顶端继续上滚可能不产生任何 `scroll` 或 `scrollend`，没有后续机会恢复锚点。适配层现在只在已有分页被滚轮打断时保留一条可见行；到顶后的滚轮间隙继续保留它，分页完成后释放。普通分页仍归官方组件处理。每次定位使用有界的视口命中，不遍历整段历史，也不修改上游实现。测试同时保存逐帧旧行位置，不能只凭最终截图判断没有跳页。

`e2e/cold-boot.spec.ts` 另查持有读者手势时，可选插件不得开始加载；还会先拦住已发出的账户插件请求，再开始第二个可信触摸手势并放行请求。该阶段的标准 preload 可以完成，但当前插件脚本也必须等松手后才执行；同时检查只发生一次传输，后续可选阶段不得继续启动；放开后恢复完整官方插件图，输入框实例和草稿保持。自有调度通过公开 `entries.sync` 逐次加入完整依赖闭包，先以标准 script preload 下载精确版本资源，网络返回后再次让出事件循环并检查读者活动，再进行官方图协调；HMR 及其可选依赖者最后进入完整图，真实的首阶段硬依赖仍优先保留。无关 Host 初始化也使用操作优先策略，主动选择的 Host 可以立即开始。该策略不能中断已经在途的单个依赖闭包或同步插件工厂，不能据此宣称所有主线程长任务已消除。

本机每轮额外用固定 `webshot` 命令重放最终视觉状态，保存手机最新位置、历史阅读、展开命令输出，以及工具面板桌面/手机截图。Agent 必须打开图像检查正文宽度、重复栏、输入区、按钮和溢出；截图生成成功不算视觉通过。截图使用独立浏览器重放，不能证明触摸过程没有闪帧，过程判断依赖同轮逐帧记录。`webshot` 的窄视口截图也不等同于物理手机的地址栏、软键盘和粗指针环境。

GitHub CI 的完整浏览器套件包含这些触摸断言并上传 JSON。CI 未安装本机的 `webshot` 时显式设置 `HAPI_DSH_VISUAL_REVIEW=off`，日志写明视觉复查未执行；不得把 CI 通过数算成视觉通过。本机 Agent 验收不设置这个开关。

线上只读触摸采样：`HAPI_DSH_TOUCH_PROBE=1 HAPI_DSH_PROBE_RUNS=1 npm run test:perf:production`。真实会话首屏出现后立即执行 12 次向较早和 12 次向较新内容滑动，记录匿名 DOM 序号和几何信息。`HAPI_DSH_PROFILE=1` 可同时输出启动与触摸 CPU profile，分析运行与普通计时分别报告。生产源持续变化，样本不是固定载荷对照，也不替代物理手机验收。

## 数据与边界

手机 earliest-boundary 四条路径也必须逐帧保留同一条旧 DOM 行：从放行分页前到提交后的每一帧，身份仍有效、偏移不超过 2px。只检查最终位置与空白帧会漏掉“有正文但短暂跳走再恢复”。2026-10-24 补充这一断言后，四条路径的提交帧分别为 6、9、9、9 帧，最大偏移均为 0px；对应四张手机截图已查看。它们仍是可信触摸驱动的 Chromium 合成源测试，不能替代物理手机验收。

浏览器执行 pinned 官方 DSH Conversation、SessionProvider、编辑器和插件加载器；HAPI wire 和执行结果为合成 fixture，不调用真实模型。发送、队列、审批、断线等测试只操作该隔离环境。生产探针只读取既有会话及页面状态；报告只存时序、计数和脱敏错误，不存正文、凭据或私有会话身份。

单次通过只说明对应环境与样本通过。最终交付同时给出源码版本、客户端构建时间、Host/浏览器启动次数、运行次数、失败项和未覆盖范围。内存窗口长期有界、跨设备通知、真实远端冷启动等，必须有各自证据，不能从短流程推断。

DSH rc.3 的展开工具历史回归连续记录三个滑动方向、方向之间的间隔和结束后的静置。不要在每个方向结束时停止帧采样，否则插件加载造成的长任务会漏记。首次 649.9ms 失败和完整诊断保留；修复及实际测量见 [rc.3 升级记录](dsh-rc3-upgrade.md)。
