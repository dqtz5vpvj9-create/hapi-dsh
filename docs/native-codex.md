# 原生 Codex 使用与恢复

这里的 Codex 会话仍由既有 HAPI 原生桥和 Codex app-server 执行。DSH 提供聊天呈现，统一工作区提供机器目录、窗格和原生控制。操作是否接收、排队、开始或最终解决，以原生系统返回的事实为准。

## 新建与创建记录

在统一新建入口选择原生 Codex，再选择在线 HAPI Runner、工作目录，以及需要明确指定的 Codex home、模型和推理强度。没有指定的模型/home 继续使用 Runner 的默认值；界面不会替换成主 DSH Host 的模型配置。开启 worktree 时必须给出 worktree 名称，实际创建由对应 Runner 完成。

每次明确提交产生一个固定创建 ID。主 Host 在向网络发送之前保存该 ID 和不可变请求，因此浏览器重开、网络断开或主 Host 重启后，仍能找到这次创建记录。

| 状态 | 已经知道的事实 | 接下来做什么 |
| --- | --- | --- |
| `submitting` | 正在提交原始创建请求 | 等待回执；不重复点击创建 |
| `accepted` | 已知 HAPI 来源会话，原生 thread 或展示绑定尚未 ready | 检查结果；只读取和接入这个已知来源 |
| `indeterminate` | 回执丢失或来源无法证明是否启动 | 保留原 ID，使用创建记录里的检查/恢复操作 |
| `ready` | 原生 thread、机器/home 和工作区展示绑定已确认 | 打开创建的会话 |
| `rejected` | 上游给出明确未启动/拒绝证据 | 根据错误修正条件后明确创建新请求 |

“检查结果”不发送创建请求。只有在来源会话未知、用户明确要求恢复时，才把**同一份请求与同一个创建 ID**交回固定版本 HAPI 的持久 claim 机制查询恢复。它不会换一个新 ID 来碰运气。已经知道来源会话 ID 时，恢复同样只做读取和 attach。

主 Host 重启后，过去 `ready` 的记录会先重新核实当前展示绑定；这不表示原生线程被重新启动。

## 原生设置

在原生会话的“原生设置”中读取实际模型目录和当前值，可调整：

- 模型及该模型公布的推理强度；选择默认强度时使用原生目录明确给出的默认值。
- 权限模式：`default`、`read-only`、`yolo`。
- 协作模式：`default`、`plan`。
- 服务级别：标准级别，以及当前模型实际公布的 `fast`。

来源没有报告的值显示为未知；模型目录不可用时显示原因，不编造可用模型。会话失去原生执行所有者或处于只读状态时，必须先恢复原生连接。

设置回执中的 `confirmed` 表示固定版本 HAPI 已等待相应原生设置通知；`observed` 表示后续读取确实发现了请求的值。超时、认证中断或断线可能留下 `indeterminate`，此时保留操作 ID 并继续读取。刷新不会再次提交设置，也不会把待确认的选择显示成已经生效。

## 从原生边界分支

会话操作可以从当前线程分支；消息上的原生分支入口可以从该条已提交消息对应的真实边界分支。展示层的消息 ID 会先映射到原生 `threadId / turnId / itemId`，不会直接冒充 HAPI 的消息 ID。

分支提交使用固定操作 UUID 和来源 revision。工作区保留上游返回的操作回执；只有子线程的原生身份存在且 binding 为 `ready` 时，才在统一侧边栏中接入并打开它。子线程已创建但尚未绑定完成，与分支没有执行，是不同状态。

遇到未知结果时，先检查原操作或明确要求 reconcile。关闭一个尚未准入的意图，也需要上游给出“未派发”的证明；关闭按钮不会凭本地猜测宣称取消成功。若用户坚持创建另一个分支，界面要求明确接受可能重复的风险，并用关联原操作的新 UUID 表达这次独立决定。

## 计划与中断

“执行计划”只对原生系统当前公布的计划提案开放。聊天正文中一段看起来像计划的文本，本身不能授权执行。

实现调用原生计划接口。固定版本 HAPI 的原生 owner 负责切换回执行模式、检查是否空闲以及队列条件，并使用提案对应的固定原生输入身份入队。工作区保留以下不同阶段：

- `submitted`：原生接口已接受请求。
- `queued`：已在原生队列中观察到对应输入。
- `invoked`：原生系统已调用该输入。
- `indeterminate`：暂时无法确认结果，仍需继续读取。

这些状态都不等同于计划任务已经执行完成。最终输出、工具结果和 turn 状态仍显示在官方 Conversation 中。同一个结果未知的提案不能通过换操作 UUID 再次提交；重启也不会自动重放它。

需要继续讨论计划时，在原会话中发送普通输入。需要中断正在执行的工作时，使用取消操作，交给原生 owner 执行 abort。关闭窗格、切换窗口或刷新页面只释放/恢复视图，不执行 abort。

## 验证边界

本仓库对以上回执、持久化、并发点击和不确定结果分支提供自动化协议测试，并用固定官方 DSH 的真实进程、Conversation 组装器及浏览器验证整合。测试中的 HAPI wire fixture 和模型 fixture 不会执行真实付费模型，也不能代替用户机器上 Codex 登录、app-server、Runner、权限及文件系统的部署验收。

对应实现是 `src/hapi/native-creation.ts`、`src/hapi/native-control.ts`、`src/hapi/native-plan.ts` 和 `src/codex/`；完整验证说明见[可复现验证](validation.md)。
