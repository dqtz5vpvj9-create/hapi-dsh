# HHPI 运行入口与恢复工具变更

2026-11-09 03:14 UTC，完整发行 `0fbb645af6280125` 已在中央 Host 与两个 Windows Runner 同版上线，使用 `.22` / 22 包的完整扩展集合。实际 consumer、认证、压缩 WebSocket、客户端模块字节与来源在线均已核对，原 Linux daemon 与 Windows app-server 身份和启动时间保持不变。本文是该次发布快照，后续运行版本以正式 bundle 的 manifest 和实际 consumer 为准。

本批修复迟到发送确认清空后续草稿，以及内置听写异常结束丢失已识别文字。源内全文搜索、权限修改后的真实状态回显已走通并保留原草稿。会话引用已包含在发行中，但该批最后的实际提交验收未进入编辑器，仍未验证；用户报告的那一次语音丢字具体触发未确认，原文未恢复。完整工作台交付仍在继续。

工作区保留三条来源：本机普通 DSH、正式配对的远端 DSH、连接原 app-server 的 HHPI Codex。普通 DSH 继续使用原 Session、Invocation、权限与公开资源 provider；Codex 保留原 machine/source/engine/nativeId。Files、上传和 PTY 只由真实源 OS 的显式 owner 提供，中央 SSH 转发不能冒充 Windows 本机资源。

旧 HAPI 登录、Hub 来源、观察/display 执行、SessionTerminal 和远端语音入口退出。新 CLI 明确拒绝旧 `hapi` 配置和登录参数，不默默忽略它们。原数据、历史输出、草稿及不确定回执继续保留；升级不会复制历史、创建替代执行、自动发送草稿或接管原 PTY。

旧链接和布局只有在精确账号、原始身份与当前目标授权都满足时才通过有限 alias 恢复。无法映射的原始地址保留并提供明确的本机导出，不按标题、cwd 或相近 ID 猜测。改变外层 Host 路由不改变内部原生身份，也不能直接复用另一 Host 的 seq/epoch 或阅读水位。

维护者同时提供独立 `hapi-dsh-offline-recovery-VERSION.tgz`。它只需 Node 24，包含对应源码与许可，不装入 DSH。浏览器“本机恢复”的导出可离线保留为可查看的草稿和附件恢复包；不会自动认领旧无账号数据。用法见[离线恢复说明](offline-recovery.md)。

完整 bundle 的安装、升级与回滚继续使用[正式安装器](distribution.md)。原 profile、私有配置、机器身份和原生记录不重新初始化。各实际 Host/Runner 必须消费同一套完整扩展；文件、PTY、通知、回滚等行为保留各自的适用验证范围。升级仍须遵守原 owner 的 idle 与健康检查，不因一个窗口关闭而终止原执行。

后续发行已包含原 Files 入口修复、Workspace 启动恢复修正及阅读位置修复；原 `.14` 的缺口不再作为这些功能的当前状态。原会话偶发空正文、设置页曾出现的整页空白，以及二级界面的可用性仍在跟进，不能由一次正常打开推定已解决。用户已要求停止进一步手机验收及帧率调优；已有结果按原范围保留，未验证项不改称通过，也不据此复制功能任务或拖延功能修复发布。
