## 本次性能调试证据

只读探针：`scripts/diagnose-federated-load.mjs`。它通过同一个生产 Host 代理读 bootstrap、官方批次和 `session/follow` 首帧；不发送、取消或修改用户消息，不打开浏览器。

- 截图中的远端 DSH Web 会话：第一轮 bootstrap 56ms；3 个官方批次共 11,346,207 字节，分别约 24/392/55ms。
- 第一轮三次新建 WebSocket：15–21ms；从建立连接前到历史首帧 87–90ms，约 1.29MB、420 条记录；JSON 解析 9–12ms。
- 第二轮负载变化后：bootstrap 21ms，串行批次约 14/465/362ms；并行取批次总计 869ms。此轮没有证明并行下载端到端更快，不能据此写加速百分比。
- 第二轮历史首帧 121–626ms，约 1.30MB、425 条记录；会话仍运行，数据量和延迟会变动。这些是服务器侧发起的真实传输测量，不包括用户网络、插件执行、DOM 渲染或绘制。

本次代码收口：共享 Host 预取官方现成批次，避免加载器按依赖临时启动下载；不裁剪实验性插件。取消每个在线 Host 刚启动就打开最近 5 个历史的预热行为，先保留主动访问会话，其余预热延后到会话就绪后的两个帧边界。增加 `host.resources / host.graph / host.ui / host.catalog` 累积计时，补上现有 `pane.reference/content/composer` 之前的盲区。


## 本轮修复（“立即全部修复”）

本轮实现以下改动；服务发布和测试结果在交付记录中记录，界面仍由用户手测。

- **启动**：Host 图初始化按当前 Pane 优先调度。后台 Host 正在初始化时，新选择的 Host 可以进入第二条初始化通道，避免慢机器阻塞前台。保留完整官方插件图和已发布的资源预取、Host 分段计时。
- **长历史缓存**：隐藏、空闲、无草稿/附件/待回答、停留在最新内容且没有文件或语音关闭保护的 Pane，在事件数超过 1500 时释放该视图与 workspace 的公开引用；下次选中重新取得官方尾部窗口。不会修改官方连续历史窗口，也不会停止 Agent。可见或正在阅读旧消息的窗口仍保留。
- **草稿**：附件按原会话身份保存，跨 Pane、跨显示代际复用；重复 Pane 只有一个附件持久化 owner，切换 owner 等待前一个写入完成。旧 Pane 键的附件首次打开时迁移。官方非空草稿与备份冲突时两份都保留，并提供“追加到当前输入框”，不会静默覆盖备份。
- **队列**：原始附件文件名进入投递投影并显示在展开列表，仍通过原有取消确认流程取回编辑，保留源路径；后续补上经过原会话授权的图片缩略图，队列折叠时不加载，不上传替代文件。
- **Goal**：原生 Codex composer 左侧增加 Goal 按钮，直接编辑原生目标，提供保存、暂停、继续、清除；不构造假提示词，不自动创建目标。
- **新建**：全局新建自动继承当前 Pane 的 Host、机器、目录及源引擎上下文，显式目录菜单继续覆盖默认值。
- **工具**：上一批本地工具行造成命令与状态刷屏，已撤掉。通过公开槽位查询实际注册的 `bash` 组件，将 CodexBash 等 shell 工具的参数和结果转换后交给该组件显示；专用插件可以覆盖别名。测试中的注册组件为 fixture，仅证明公共注册与参数适配链路，不代表浏览器验收。
- **外观**：使用官方品牌槽显示 HAPI，保留插件/自动化入口；收紧 Pane 标题，FAST 改为小图标，机器行补图标，按真实机器 ID 去重。不会按相同 hostname 合并不同机器。
- **发布**：`npm run deploy` 完成类型检查、逻辑测试、客户端构建和 HTTP 检查；`npm run deploy:host` 另外在构建后检查普通 DSH 执行状态，只重启展示 Host。两者不跑浏览器、不重启 HAPI Hub/Runner。

### 仍不能报告为完成的部分

1. 缓存回收不等于可见长 turn 的虚拟化。冷启动、长 turn、13 Pane、缓存 <500ms 和切换 p95 <150ms 仍需实际客户端计时；本轮没有声称这些指标达标。
2. 草稿、引用、附件、原生待回答分别已有持久化；跨 generation 阅读定位及所有富状态的单事务迁移仍未完成。原生待回答早已按 Hub / 原会话 / request ID 保存，不能再误写成完全不持久化。
3. 队列编辑按原生语义先取消并确认，再取回 composer；文件名、授权缩略图和原路径引用已实现，不在源队列中偷偷改写附件或自动重发。
4. 旧 Terminal 协议不提供 Runner 逐条 ACK，只能确认适配层接收；本项目没有修改原 Runner 的授权，不能伪造 ACK。未确认的输入不会重放。
5. 实验插件兼容按执行所有者区分，见 `plugin-compatibility.md`。保留官方页面/注册不代表第三方原生引擎自动执行 DSH 插件。
6. 移动键盘、旋转、OS 推送、跨设备和视觉满意度仍由用户实际验收；逻辑测试不能替代这些结论。
