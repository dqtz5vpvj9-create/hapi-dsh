## 主要发现

| 优先级 | 基线中的问题 | 来源及后果 | 本轮处理范围 |
| --- | --- | --- | --- |
| P1 | 源事件 Promise 链无界积压 | `073886ef`、`1cdb2e7`。慢消费者阻塞时，每个排队闭包仍持有累计正文；Map 只有一个尾 Promise 不能限制内存。 | 与已修 sliced string、ScopeIndex 分开。现有隔离实验曾测得 1,024 份累计快照约 257 MiB 的额外留存；仍需具有正确顺序和补全语义的队列修复。 |
| P1 | 旧缓存先显示，当前正文等待全历史 | `9e459db` 引入，`58800d1` 默认启用；Native 和 observed 两条路径都有。epoch 表示结构身份，不表示缓存已包含普通追加。 | 两条路径改为先读有界最新尾页，并保留源不可读时明确 stale 的缓存回退。旧实现负对照已失败；新 Native 54 项、observed 23 项逻辑测试通过。 |
| P1 | 展示代切换先退旧视图，新正文尚未就绪 | 初始 generation replacement 后，缓存后台补全增加了正常切代次数；reference ready 被误当作用户可读。 | 真实浏览器负对照见过约 188 ms 正文空白。新实现只在精确同源切代时保留一个不可操作的旧官方视图，新正文、输入框和阅读定位就绪才交接。 |
| P1 | 同源新 Composer 关闭后，旧 Composer 失去保存权 | `806b1f0`。仍存活的旧对象保留订阅，却不再是 owner，后续编辑可能不保存。 | 独立负对照及修复验证中；不能用“同一 Composer 两个 pane”测试代替不同代对象的关闭顺序。 |
| P2 | 首次设置插件加载失败后不能重试 | 延迟插件加载在失败前锁定 started；再次打开 Settings 直接返回。 | 独立修复验证中，要求首个请求失败、第二次成功，成功后不重复加载。 |
| P2 | 已访问源的显示历史长期留在 Host | 早期 service 的 Agent/投影/历史持有关系仍在；on-demand 仅减少首次 attach。 | 未解决。需要显示数据的字节预算及无读者时的释放，保留原生执行、未决投递和审批事实。 |
| P2 | 旧测试把最终正确或任意正文当作体验正确 | 早期 opening 信号不检查最新源尾部；探针首个正文出现就停止；手机边界测试只核对提交后的最终偏移。 | 新观察器要求源端独立确定的最新正文与已知标题，并检查后续回退。手机边界已增加固定旧行逐帧检查。 |

这些问题叠加后的因果链是：先用旧缓存迅速绘制，让指标提前成功；后台读和投影完整归档；再替换展示代，短暂丢掉正文或标题；所有已访问源的显示对象和来不及处理的事件继续占内存。因此，小样本测试、热切换和 HTTP 可用都可能通过，而长会话冷打开、弱网和连续手势仍然很差。

## 谁引入了这些设计

Git 作者不等于实际写代码的模型。按实际本地编辑调用和当时 model metadata，可确认：

- `58800d1` 默认开启 `fastHistorySeed`：`deepseek-official / deepseek-flash`。
- `9be022b1` 的 recent-view 复用、缓存 epoch 条件，以及 `c366dad5` 的小 opening cache/单页 tail：`gpt-6-astra`。
- `1dad739` 的 observed final-tail 局部修改和提交执行：本地 DeepSeek；不能据此认定该提交全部代码都由它写。
- `073886ef`、`1cdb2e7` 和 `9e459db` 的最初编辑模型未确认。未找到本地记录不能证明来自网上 GPT PRO。

详见[冷打开设计来源证据](cold-opening-provenance.md)及 1–23 审计中的局部工具调用记录。问题经过多个实现和默认策略变更累积，不能给整套架构指定一个没有证据支持的作者。

## 验收范围

当前修复与测量详见[冷打开结果](cold-opening-freshness.md)、[UI 验收约定](ui-acceptance.md)和[内存拆分](memory-breakdown.md)。本轮冷打开用例使用固定 rc.3 的真实官方 Host/Conversation、合成源及显式网络门；真实保存尾页回放仅覆盖 26 条源记录，不包含其完整归档，也不是用户网络的生产测试。

手机四条加载边界路径的逐帧最大漂移均为 0px，四张截图已查看。冷打开同时覆盖旧缓存、新消息、阻塞归档、草稿及只有一个可操作输入框。观察器另有独立负控，避免隐藏视图、屏幕外文本、透明的待交接视图或最终 DOM 恢复掩盖错误。

这些证据不能关闭长期 OOM、所有已访问源的内存预算、完整长归档投影、跨平台干净安装和物理手机验收。后续必须按具体场景继续验收，不能继续用单测通过数代表“已经像 HAPI 一样可用”。
