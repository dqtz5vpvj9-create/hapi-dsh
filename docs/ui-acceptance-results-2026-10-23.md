# 2026-10-23 实时更新与 UI 性能修复验收

实现提交：`9be022b`。这批修复已发布，实时更新、草稿和手机结构的定向检查通过；**完整性能验收未通过**。连续滚动五轮中三轮超标，CPU 降速的线上首开仍然很慢，不能宣布达到 HAPI 的整体体验要求。

## 修复内容

- 原生 Codex 和其他 HAPI 来源的 assistant stream 曾重复使用同一个 revision。官方 DSH 累加器要求每个 start/chunk/end 帧连续递增，现在投影按该协议发送，避免增量被拒收和反复重建基线。
- 实时源状态、索引增量与归档历史分开调度，避免排在四个全量历史任务后面。普通索引通知先读最近 32 条，按已知边界补页；结构 epoch 变化、回退和缺口继续使用完整核对流程。并发归档不能覆盖已收到的新消息。
- 冷打开优先当前 Pane，等待真实正文、输入框及首次绘制，再启动无关 Host；折叠侧栏跳过列表构造，目录接口消除逐条重复扫描。
- 语音 SDK、长图导出改用官方包内分块接口按需加载。聊天主包从约 3.03 MB 降至 1.77 MB；语音弹窗和实际 PNG 下载均有浏览器覆盖。
- 最近访问视图只保留两个且限制历史规模；阅读锚点改为命中测试和有序查找。滚动在接近历史边界时才查询翻页控制。试验过的 `content-visibility:auto` 覆盖与官方隐藏规则冲突、实测也更慢，最终已移除。
- 回执恢复入口移到 Pane 标题栏状态按钮，输入区只保留需要操作的队列。没有修改上游 DSH 源码，也没有重启 HAPI Hub 或原生执行器。

## 线上只读导航

使用实际 HTTPS 入口、Chromium 390×844 手机模拟，网络未降速。计时从 navigationStart 到真实消息节点和可编辑输入框，不以骨架、工作区标志或热切换代替。

| 样本 | 正文 | 输入框 |
| --- | --- | --- |
| 本轮修改前的普通新 context | 4.54s | 3.88s |
| 最终普通新 context | 2.77s | 2.26s |
| 最终同 context 再次导航 | 2.11s | 1.84s |
| 最终 CPU ×4 新 context | **19.01s** | **16.64s** |
| CPU ×4 额外诊断采样，开启 CPU profiler | 11.85s | 9.34s |

这些是单次样本，不是生产 p95；前后会话和主机工作负载可能变化，不能用它们证明稳定百分比提升。CPU ×4 的主线程长任务最高约 4.9 秒，profile 指向官方模块初始化、视图测量及渲染；19 秒样本还有多条 RPC 数秒等待，需要继续区分网络、服务端排队与浏览器调度。普通首开有改善，慢设备仍未达标。

静态 JS/CSS 路径已启用 Nginx gzip，实际浏览器响应确认 `Content-Encoding: gzip`；WebSocket/事件流保持原配置，生产探针未报告页面或 socket 错误。首开仍传输了约 6.3 MB：压缩生效不等于资源已足够小。

此次 Nginx 修改仅在原代理 location 下加入静态类型压缩，保留 TLS、访问限制、认证、Cookie 和禁用访问日志设置。第一次子 location 缺少 proxy_pass 导致 404，已立即恢复后修正，最终检查为 200。原配置备份在 `/mnt/cache/data-cache/hapi-dsh-tail.pre-assets-gzip.conf`；回退时将其恢复到 `/etc/nginx/sites-available/hapi-dsh-tail.conf`，先 `nginx -t` 再 reload。此备份属于七日临时目录。
