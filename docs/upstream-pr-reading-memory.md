# Draft upstream proposal: optional semantic Chat scroll memory

No upstream pull request has been submitted.

Mobile shells can restore a conversation after process eviction, but the official Chat view currently keeps its semantic reading position only in a graph-local map. Add an optional `chatScrollMemory.forBinding(binding)` provider returning `read()` and `save(ChatScrollPosition | null)`.

The provider receives the exact validated Session binding. A shell can persist source/account/Host-scoped positions, while the official reader and virtualizer continue to capture and restore the exact anchor, semantic owner and relative offset. The extension does not manipulate DOM scroll positions, widen execution authorization or change a native Session's identity.

The existing in-memory map remains the default when no provider handles a binding. `__DSH_CLIENT_READING_MEMORY = 'off'` and `DSH_CLIENT_READING_MEMORY=off` independently disable the provider path. Persistence limits, storage failure handling and account lifecycle remain the hosting shell's responsibility.

The source change is generated by `scripts/dsh-ext/reading-memory.mjs` against pinned upstream commit `1f81c047fc48fa190a683e469daa699857e9afe8`, and its source hash participates in the complete extension provenance. `tests/contracts/hhpi-reading-occurrences.test.ts` executes the actual official view injection and validates default behavior, durable semantic positions, independent occurrences, stale-owner rejection and capability-off behavior. The prepared-source loader is an isolated test boundary; it does not modify installed packages or replace the production reading implementation.

The companion HHPI cache saves complete accepted reader windows under bounded authenticated storage. Those product-specific limits and source recovery semantics are documented in `docs/adr/hhpi-durable-reading.md`; the upstream contract remains generic and optional.
