# Original HAPI sidebar actions

This is a source-based audit against HAPI `0f8ef697`. The original row action adapter and source-successor draft hand-off are implemented. All three actual-browser sidebar cases passed on shared build `21781`, including keyboard focus, split navigation, export, source confirmations and touch long press. Both draft hand-off cases passed on build `31690`; the later build changes only first-menu keyboard focus. The unified sidebar owns navigation and geometry only. Source mutations use their existing durable operation controllers, and plugin views use official DSH tab registrations.

## Actual upstream entry points

The row in `web/src/components/SessionList.tsx` passes its original HAPI ID and `metadata.agentSessionId` into `SessionActionMenu`. It supplies current/below/beside navigation, rename/title suggestion/summary, project/global pin, export, mark unread, Codex-home migration, archive, restart, reopen and delete. `SessionActionMenu.tsx` also accepts Files, Changes, Terminal and outline callbacks for other callers; their presence in the reusable component alone does not prove that every list row supplies them.

`web/src/hooks/useLongPress.ts` defines a 500 ms gesture, cancellation on movement, keyboard ContextMenu/Shift+F10, and a bounded 700 ms suppression of touch-generated compatibility mouse activation. The anchored menu is portaled outside contained panes, clamps to the viewport, focuses its first enabled item, and closes before invoking its action. Reopen may produce a new source session ID; the source then transfers the composer draft and pending share intent before navigation.

## Validation and boundaries

Focused tests pass across `workspace-sidebar-actions`, `workspace-source-export`, `workspace-source-pin` and `workspace-native-admission`: identity selection, source-state eligibility, long-press timing/movement/cancellation, bounded click suppression, export settlement and warning admission. All three `e2e/sidebar-actions.spec.ts` cases passed on build `21781` (24.8 s combined): desktop mouse/keyboard navigation and source actions, live/inactive confirmation admission, and a real CDP touch long press. The desktop case verifies exact clipboard identities, both pin modes, the first enabled menu item's actual focus, below-pane geometry, unchanged original draft, title suggestion without automatic save, and downloaded source JSON. The mobile case verifies viewport bounds, compatibility-click suppression and a subsequent intentional activation. Both navigation cases assert zero chat writes and zero browser page errors; confirmation tests assert zero lifecycle submissions. Final desktop and mobile screenshots were inspected.

The first acceptance runs exposed real capture-phase unmount, portaled touch compatibility-click and hidden-render focus bugs. Those were fixed in production code and the same assertions passed; the tests do not force a click, manually focus the menu item, or bypass the original action handlers. The temporary Chromium executable was also restored after environment cleanup from the same official Chrome for Testing `156.0.8078.4` archive, SHA-256 `c3e50596aef52c58f8fda3c6b3411c33d34c88b177b3ed1c2243359fd3b8ba20`. The browser version and upstream bundles were not changed for the rerun.

## Confirmed successor draft hand-off

`draft-handoff.ts`, `draft-handoff-receiver.tsx` and `draft-handoff-dialog.tsx` implement one explicit per-window transaction. Native and observed source tools call it only for confirmed reopen/resume or observed migration receipts. Ordinary navigation, imports and forks do not imply that a draft should move. The controller verifies the original Hub and serving Host against both catalogued source identities before selecting a target.

The original live official input contributes text, semantic reference occurrences, command token, its exact binding and draft revision, attachment IDs and original `File` objects. Those bytes are stored in an IndexedDB transaction before the old pane is replaced. A temporary own-view lease parks the old graph, disables its navigation and input routing, and releases it after settlement; closing the Host still forces disposal. No foreign `SessionReference`, private editor node or upstream storage payload is accessed.

The target uses public `InputActions`, `SessionInput.insertReference`, the command registry's read-only resolution and the real attachment owner's callbacks. An existing target requires the explicit Append button. Changed target text, reference revision or attachment identities veto an outdated choice. Only a durable acceptance proof followed by matching live target and source bindings permits old-draft cleanup. An interrupted or unknown transfer is not replayed. A source changed during the operation stays intact, and the UI states that outcome.

Only a same-window inbound share with an untouched `ready` receipt can follow the confirmed new original source ID. Inserted, inserting and uncertain shares remain attached to their original receipt. The hand-off holds share insertion until the user settles the draft comparison. Done performs the existing shared editor prepare/verify checkpoint and checks the actual target again; a failed attachment write or concurrent edit keeps the hand-off backup. This action never submits a message.

Ten focused hand-off cases exercise append admission, exact live binding and File identity, source edits, a changed target during the proof write, failed persistence, uncertain recovery, forced Host disposal and Done's durability barrier. Both real-browser `draft-handoff.spec.ts` cases passed on build `31690` (45.1 s combined). They exercise actual official inputs, source restore confirmations, attachment callbacks and IDB: text and original attachment bytes survive refresh; the unchanged predecessor clears only after acceptance; an existing target needs explicit Append; an untouched pending share follows the confirmed source and inserts exactly once; neither case sends a chat message. The source reopen route is an explicit wire fixture, not a real native CLI.

The unused client `NativeFiles` and `NativeDocument` renderers have been removed. New files, document previews and terminals are exclusively owned by official DSH plugins with source providers. `legacy-session-terminal.tsx` retains only the schemaVersion 2 SessionTerminal compatibility view, its exact old terminal ID, source protocol and detach-only cleanup.

The HAPI wire used by these integration tests is explicit fixture data. A test proving a source operation was routed once with its original identity does not prove a physical Runner, external CLI account, or destructive action on a real user's session was exercised.
