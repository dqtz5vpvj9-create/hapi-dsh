# 官方聊天阅读器的布局测量修复

用户批准 `client-ui-chat` 后，运行时修改始终限于该包：`VirtualChatRows` 处理几何与恢复期范围，同包契约及滚动接线提供可选的既有导航状态查询。对线上包先作源码重建，`client.js` 与 `index.js` 均逐字节一致，再在相同基线上应用增量。其他 13 个生产扩展包保持原字节。

修改将行几何读取和尺寸更新分成两批，复用同一模型已经接受的尺寸；ResizeObserver 负责内容高度、宽度和显示状态变化。列表边距在挂载及真实布局变化时测量，不再随每次 React render 无条件同步测量。隐藏窗格保留有效尺寸，恢复后等待真实尺寸再提交。原来的官方提交、位置恢复、跟随判断和精度保持不变，没有另加滚动补偿器。

可复现源码增量在 `source-snapshots/dsh-ext/ui-chat-layout.patch`，应用于原有源码准备变换之后。完整 UI 包源码、ADR0009 和上游 PR 草稿随发行包提供。开发构建也补齐了三个已批准原生包，完整集合为 14 包；逐包来源身份允许保留已有 UI 包和独立的原生索引源码身份。

组件回归覆盖不变渲染零重复几何读取、内容增长、隐藏恢复、宽度变化，以及原有固定位置跟随断言。首轮检查覆盖 56 个文件的 876 项组件用例；其中两个旧预期补齐已部署的 anchorOwnerKey 和准确的 occurrence 拒绝契约，ResizeObserver fixture 也改为分发所有观察者，没有删掉跟随断言。

安装后的官方 DOM 契约 9/9 通过。桌面/手机浏览器场景分别为 27.256/53.561 秒，原有每条 60 秒预算和 2 像素门槛保持不变；连续 13 段更早历史的提交锚点均为 0。2,048 轮合成原生来源从导航到首段正文为 840/855 毫秒，仅读取七组正文。详见[浏览器记录](hhpi-layout-browser-results-2026-11-05.json)。

这些结果证明功能和实验室阅读契约。生产站点的 80 毫秒帧门槛需要在正式部署后单独执行；启动、主动宽度变化等阶段的诊断最大帧间隔不能替代该门槛。实体手机和软键盘仍未执行硬件验收。

这部分修改尚待与官方布局的后续修复共同进行正式发布及生产帧验收；不能将前一版描述为已解决全部卡顿。


## 按实际 DOM 变化复用行高

后续修复不再把整个 rows 数组作为尺寸有效期。实际挂载元素保留已接受的 border-box 高度；MutationObserver 只使发生文本、子树或属性变化的行失效，单纯的 data-index 重排不触发重测。父 layout effect 同步消费本次 React 提交尚未分发的变更记录，然后批量读取失效行，最后才更新虚拟器并交给原来的官方 afterLayout 完成位置恢复。ResizeObserver 在确认真实尺寸前也先消费记录，避免同一变更在随后再次使尺寸失效。观察器自身不发布 React 状态，不创建第二套提交循环。

组件测试直接重新创建 rows 对象及 render 闭包，确认实际 DOM 不变时零次几何读取；data-index 改动也为零。文本、子元素和样式变更分别只读取一行，即使 ResizeObserver 尚未交付，列表总高度和 layoutReady 仍准确。隐藏时改变正文不会提前确认尺寸，重新显示及宽度变化仍等待真实测量。四个相关文件的 229 项测试和 TypeScript 构建通过；随后新增的隐藏正文变更断言也单独通过。正式安装后的浏览器及生产性能结果另行记录。


本轮 whole-tgz 安装后的官方 DOM 契约再次 9/9 通过，默认桌面和手机浏览器场景分别为 25.923 秒、53.450 秒。两端均连续提交 13 段更早正文，全部实际锚点位移为 0；另一 Pane、缓存往返、输入组合、普通和巨型工具、图片以及宽度重流检查通过。空投影索引的 2,048 轮原生来源，从导航到正文为 970/837 毫秒，Host 进入到首次正文为 151/157 毫秒，均读取七组正文。只读阅读、原位恢复写入权限和 warm reopen 也通过。日志为 `hhpi-layout-next-installed-dom.log` 与 `hhpi-layout-next-installed-browser.log`；报告位于 `.tmp/hhpi-browser/results/report.json`。这次实验室结果不等同于正式生产 80 毫秒帧门槛通过，后者仍待发布后执行。

## 前插期间保留已有可见范围

第二轮正式部署 `r-f59f11…` 后，生产帧门槛仍未通过，桌面为 117 毫秒、手机为 150 毫秒。新增的匿名 DOM 变更诊断发现，每次前插后的第一次测量中，16–22 个挂载行里有 14–21 个是新元素；同一次发布随后又创建另一批行。属性变动主要是 style 和 data-index，排除了“忽略更多语义属性即可解决”的判断。真正的问题是旧 scrollTop 先在前插后的新坐标中挂载了错误区间，再测量、校正并挂载正确区间。

后续修复在已有阅读 seat 的稳定行键全部统一向后平移时，暂时将上一挂载范围的键映射到新索引，不再同时挂载旧 offset 算出的无关范围。原官方视口发布 programmatic landing 或观察到真实新 offset 后，恢复正常 overscan；初次观察和相同旧 offset 不解除。显式跳转提前使用已有 navigation.navigating 排除该过程，目标不会被范围保留挡住。没有新增滚动写入、另一个锚点 owner、较小 overscan 或新的高度常数。

实际虚拟器回归前插一百行，确认 landing 前 DOM 键完整保留且零几何读取，相同旧 offset 事件也不破坏它；官方 landing 后，更早邻行正常进入。首次回归捕获 paged jump 和 Turn 边界控件两项退化，修复后原有落点、aria-current 和控件断言全部通过，没有放宽预期。相关两文件 169 项、其余两文件 60 项通过，随后新增的旧 offset 断言及 TypeScript 检查通过。新包安装与正式生产帧验收尚待执行。
