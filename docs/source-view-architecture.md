# 源消息窗口与稳定执行归属

本文记录 V4 的 SourceFrame 实现。HHPI 的目标是通用 Agent 远程接入 DSH Web，HAPI 仅为参考或可选接入来源；消除事件往返及客户端坐标重映射的目标方案见 [HHPI 远程接入架构](hhpi-remote-access-design.md)，尚未实现。

HAPI 的消息身份和游标是正文的数据依据。Host 生成带源身份的官方事件帧，客户端维护一个源窗口，再由一个投影步骤生成官方 Conversation 所需的数字坐标。原生执行、审批、队列和操作回执继续归同一个 Agent 与 DSH Session 所有。

## 数据路径

1. 历史页通过 HAPI context/before/after 游标读取。`HistoryProjectionSink` 使用官方事件与 surface 校验器运行 Native/Observed projector，不创建 Session、Agent、Scope 或临时运行时。
2. `toSourceFrames` 把消息、turn、step 与事件引用编码为源身份。独立分页与实时投影可产生不同的局部序号，但同一源项拥有同一个 key。epoch 只表示读取快照，不参与消息身份。
3. `SourceHistoryWindow` 返回这些帧及源游标。Host 以 HAPI session 和游标缓存已投影页，使用 32 MiB 总量、每源 8 MiB、最多 8 个源的 LRU 上限；正文页仍不分配 Host 显示坐标，也不为了打开或翻页读取目录。
4. 实时正文经 `SourceFrameFeed` → `sourceWindowFollow` 独立读取流发送，不写入操作 Session。订阅先原子地取得当前基线，再接收变化；每个慢读者最多保留一个批次，积压时改发当前有界基线。取消或释放视图会释放订阅。未完成输出和完成项使用同一个稳定 key，取消会删除未完成项。
5. 客户端 `SourceWindowStore` 合并、修订和保留一份连续源帧窗口，并统一生成官方事件序号、turn/step 与引用。窗口以 800 个源组、8,000 个事件、8 MiB 为上限；裁剪时保留所有已注册读者与刚接收的整页，游标可向前回读缓存页。`SourceRecord` 负责导航请求、视口保留和 SessionFace 组合；执行命令仍交给官方 Session owner。

普通 DSH 会话走原有路径。官方 Conversation、编辑器和插件 slot 继续使用，不维护第二套聊天渲染器。旧协议输入的客户端适配器只用于旧记录或 fixture；新 Host 正文统一发送显式源帧。

## 生命周期

同一源会话的历史修改、回退和重同步替换正文窗口，保留 Agent、Session、display id、输入和操作归属。准备新正文期间，旧 owner 仍是唯一命令入口。只有真实源身份变化或视图退役才释放相应 owner。

子会话正文改写保留子视图 owner；子会话真正被删除或改变 lineage 时只退役对应的只读子视图。删除后重新出现使用新的视图 id，避免复用官方客户端已经标记 removed 的对象，父 owner 保持连续。

Host 的纯投影保留有界源行和事件预算；超过预算时裁去旧的完整 turn 并重建纯投影，当前不可拆分 turn 保持完整。操作 Session 只承担状态、命令与操作回执，其 follow/page/projections 保留官方传输语义，不存储正文副本，也不偏移其传输序号。

真正的历史改写递增 `historyVersion` 并发送 `reset`；内存裁剪不会递增。每个正文流实例拥有独立 `historyId`，用于识别 Host 重启后的缓存失效，避免新实例的版本零与旧缓存混淆。客户端收到改写或重连时发现实例或版本变化，会撤销在途导航、清理旧游标并替换唯一正文窗口。相同版本的重连基线只补充当前尾部，保留已经读取的历史。正文首包到达才算正文 ready，操作流先连接成功不能替代这个条件。

## 导航与视口

阅读位置和回退动作使用稳定消息身份。客户端数字 seq 是视图坐标，不作为 Host 历史操作的依据；回退仍须由 Host 验证为已执行的原始用户输入。附件仅授权当前视图实际收到的帧，epoch 变化、历史改写、退役与并发读取仍遵守撤销规则。历史页在读取和投影结束时均复核改写版本；旧响应不能重新授权附件或回退边界。父视图和子视图的独立正文流都按确切 Session 资源授权。

目录独立于正文 ready，可处于 partial 或 degraded 状态。最新 head 独立读取；目录分页不附带 transcript 请求。每次导航在异步解析前取得 jump token，迟到结果不能覆盖正文、游标或新请求的忙状态。

补页预检查从当前窗口派生，保留相同视图坐标后再合并，避免与实际提交采用不同排序。首屏填充按视口缺口使用 20、80、200 条源消息；交互式上翻和向后续读按 50 条 HAPI 常规页预算提前预热并提交，不等待额外 turn 边界。DSH 每条原始消息会展开成多个展示事件，50 条可限制一次 React 提交的事件扇出；交互视口安装后预热相邻页，每次成功提交后继续预热一页。补页始终固定当前真实阅读范围，不能把“跟随底部”解释为可以丢弃旧阅读行。完整窗口符合事件与字节预算时保留全部已读内容；只有超预算才从翻页的反方向释放完整源组，且不得触碰任何可见读者。源组数量不能替代渲染高度，DOM 的显示范围不授权删除正文。

正文投影保留未变化事件的对象与数字坐标。发布端将一次连续扩展提交为一个 `prepend` 或 `append` 批次，相同窗口不重复通知；修订和真实裁剪才使用 `replace`。阅读恢复依据源正文 `historyId`/`historyVersion` 的变化，普通分页或修订的 `replace` 不等同于断线重连。普通 DSH 会话保留原有恢复语义。

HAPI 源码对照、Pane 独立窗口与官方提交能力的接入方略见 [连续历史设计](continuous-history-design.md)。当前 `SourceSessions` 主路径尚未接通 `historySource`/`windowCommit`，不能把本轮连续窗口修复称为完整迁移。

折叠工具可以收到更早内容而保持相同的外层 DOM 标题。源游标推进只证明数据页提交，程序化读取还须等待官方 mounted reader 完成布局；它不再通过 50 ms 轮询提前结算。自动和手动读取共用官方导航，发布前由官方 viewport 重新采集位置并在 layout 恢复，源路径不再维护额外 DOM 锚点。发布验收要求三次向上阅读实际出现更早的可读内容，不能只数数据页；相同游标、向后游标和历史换代均不算更早数据页。

每个 SessionOccurrence 独立管理候选窗口和取消。一次打开使用 5 秒前台预算，隐藏时暂停；超时保留编辑器与草稿并显示重试。同步消息进入数据队列不受滚动手势或其他 Pane 活动阻挡，保留窗口时保护所有已注册读者范围。

## 验证边界

纯投影等价性、源帧合并、真实官方 assembler、独立正文流的取消及背压、同 owner 重同步、迟到分页和附件授权均有针对性契约测试。测试必须断言可观察结果，例如正文旧值被替换、重复帧只显示一次、输入和队列仍属于同一 owner，不再要求旧的 Host 虚拟序号或重建代际。

新增或修改这些路径时，按 [测试说明](testing.md) 先运行相关用例，再执行发布检查。真实正文、输入、滚动和多 Pane 体验需要发布后的两条有界浏览器场景验证；单元测试通过不能推导与 HAPI 等同的可用性。当前实现及发布结果在任务完成报告中记录，旧构建的通过记录不作为新协议的验收证据。
