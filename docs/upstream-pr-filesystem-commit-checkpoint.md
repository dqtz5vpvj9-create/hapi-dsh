# Draft: expose atomic byte writes and an optional authority checkpoint

An application may stage a replacement while its caller's authorization changes. Give `FileSystem.writeText` an optional sixth `beforeCommit` callback, after the existing `sandboxPolicy` parameter. LocalFileSystem awaits it under its current target lock after staging and permission preparation, then performs the final cancellation check and existing native publication. Opted-in guarded writes recheck their version/create intent after staging. SandboxedFileSystem preserves its policy fence and forwards the callback.

Omitting the callback retains the current path. A callback rejection leaves the destination unchanged, cleans staging and preserves the original refusal object. Existing POSIX modes, guarded-create no-replace publication and Windows DACL/ReplaceFile behavior remain in their owning implementation. This is a current-authority checkpoint, with the same external-writer limitations as ordinary guarded writes.

Focused validation in the prepared rc.1 source passed 32 tests across the new LocalFileSystem checkpoint suite and existing SandboxedFileSystem suite; the three affected package TypeScript projects also passed. Windows call ordering uses explicit native-boundary fixtures on Linux and is not presented as a native Windows run. This document is an unsubmitted draft; no upstream push or publication was performed.

The same filesystem service also gains `writeBytes(target, Uint8Array, expected?, signal?, sandboxPolicy?, beforeCommit?) -> FsByteWriteOutcome`. The outcome contains create/update status and version, without text-diff fields. This lets application upload consumers preserve exact binary content through the existing atomic publisher and Windows DACL handling. Local text and byte writes share their target lock and publication helper; SandboxedFileSystem fences both. Providers without byte support reject explicitly, leaving existing callers unchanged.

The additional byte checks passed 50 local/provider/sandbox cases and one real app/Loader composition case. Existing local write/edit/atomic I/O regressions passed 199 cases, with four existing platform skips. All three package projects and their exported API documentation checks passed. Source package lists and normal deployment paths are unchanged; the extension still affects only the filesystem definition, local provider and sandbox provider.
