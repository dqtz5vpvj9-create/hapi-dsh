# HAPI-DSH 内存分析：2026-10-24

已经确认一个流式字符串保留缺陷：保存新增文本的 `slice()` 会让 V8 保留整份累计正文。连续保存这些切片，相当于保留所有历史前缀，空间随更新次数近似平方增长。修复使 Codex 和其他源会话的增量拥有独立的字符串存储，并保留全部 UTF-16 代码单元，包括跨块的 emoji 和未配对 surrogate。

生产日志另有多次 V8 接近 4GB 后 OOM、服务自动重启的记录。其中一次进程运行约 32.5 分钟后失败。这能够造成连接中断和重新加载，但没有崩溃前的 heap snapshot，不能把全部 4GB 都归因于刚确认的字符串缺陷，也不能把加载慢全部归因于 OOM。

后续验证确认字符串修复还不完整：`5784b23` 发布后的 worker 又在约 14.4 分钟时达到 4084.5MiB，因 OOM 自动重启。此时执行的是前端发布流程，它没有调用服务重启。新的 45 秒低开销分配采样中，heapUsed 从约 724MiB 增至 1023MiB；采样到的主要存活分配来自响应 JSON 解码、投影和消息冻结。分配栈不能代替持有链，不能据此把这些分配全部归为同一个缺陷。下面另列出了随后实际复现并修复的 scope 持有链，以及仍未处理的队列积压。

以下数字除特别注明外均用 MiB（1,048,576 字节）。测量对象、时刻和统计口径不同的数字不能直接相加。

## 1. 已复现的流式内存放大

每个独立 Node 进程先做 GC，随后输入经 JSON 解码的累计 ASCII 正文；每次新增 128 字节。旧机制对照只保留 `slice()`，修复组使用真实 pinned DSH Session 和本项目两种 projector，分别测流式进行中与写入历史后的留存。每个结果均扣除该进程基线，再做 GC。

| 累计更新次数 | 最终正文 | 旧切片机制留存 | 修复后 Codex：流式 / 历史 | 修复后其他源：流式 / 历史 |
| --- | ---: | ---: | ---: | ---: |
| 512 | 64KiB | 16.06MiB | 0.344 / 0.443MiB | 0.350 / 0.464MiB |
| 1,024 | 128KiB | 64.12MiB | 0.537 / 0.714MiB | 0.539 / 0.723MiB |

这是本轮全量测试的原始样本；旧组是失效机制负对照，不能冒充运行整个旧 Host 的结果。它说明正文翻倍时，旧保留量约变为四倍。若每次增长 d 字节，共 n 次更新，所有前缀合计约为 `d × n × (n + 1) / 2`；最终正文只有 `d × n`。

修复只复制新增 UTF-16 单元，不复制整份累计正文，不改上游、不提高 Node 堆上限。回归同时检查流式文本、最终正文与持久化事件一致；还修正了其他源最终消息增加尾部时，`block-end` 仍使用旧正文的问题。

复现：

```sh
node --import tsx --test tests/source-stream-retention.test.ts
```

回归使用独立 `--expose-gc` 子进程，覆盖两种载荷规模、两种 projector、文本/推理、全部 UTF-16 代码单元及跨块边界。旧机制负对照必须确实呈现超线性留存，否则测试不能声称证明了修复。当前运行时为 Node 24.22.1、DSH 0.2.1-rc.3。

## 1b. 子代理归属索引重复持有累计正文

`ObservedScopeIndex.facts` 原先按每次广播的 `row.id` 保存整份 `data`。Hub 会替换同一原生文本快照，但广播使用新的行 ID，因此归属索引留下了每份旧正文。1024 次更新后，最终正文只有 512KiB，旧索引却保留约 257MiB。这个复现不需要阻塞消费者；同一行 ID 的对照仅保留最新一份，证明问题在历史快照持有关系。

修复后，归属索引只保存身份、父子关系、精确 Task/Agent prompt、完成与错误等实际使用的字段。全文仍由原来的会话内容负责，索引不再额外引用原始 `data` 或 `message` 对象。消息身份和源端终态没有被删除或截断。

| 更新次数 | 旧源码索引堆增长 | 修复后子代理路径 | 修复后 SDK 路径 |
| --- | ---: | ---: | ---: |
| 512 | 64.44MiB | 0.321MiB | 0.316MiB |
| 1024 | 256.86MiB | 0.544MiB | 0.565MiB |

这些是独立 Node 进程的 GC 后基线差，源数据全部为合成文本。`node --import tsx --test tests/source-scope-retention.test.ts` 保留原机制负对照及两种修复路径；另有精确 prompt、错误详情、别名解析、父子关系及 wait/close 终态保护回归。索引的身份数量仍随历史行数线性增长，尚未建立全局字节预算。该旧实现来自 `1cdb2e7`，Git 作者 Shinn；现有证据不能确认最初使用的模型。

## 2. 生产 Host 的重启后基线

这是显示 Host 的 Node worker，在自动重启后、只读打开普通远端 DSH 会话期间的采样。该次快照没有发现 `NativeCodexAgent`、`NativeProjector` 或 `ObservedProjector` 实例，因此不是此前长期流式运行的重负载状态。

| 口径 | 占用 | 含义 |
| --- | ---: | --- |
| RSS | 272.26MiB | 整个 worker 的驻留页，包含 JS、外部存储、运行时和分配器等 |
| JS heapUsed | 125.63MiB | 当时已使用的 V8 堆；不是 GC 后的严格存活量 |
| JS heapTotal | 131.25MiB | 当时 V8 已分配的堆容量，包含 heapUsed |
| external | 27.43MiB | Node 统计的外部内存，与 RSS 有包含关系 |
| arrayBuffers | 23.29MiB | external 的子集，不能再加一次 |

45 秒分配采样期间执行三次只读远端导航，heapUsed 在约 125–144MiB 间波动，末次约 128MiB；这段短采样没有重现持续增长。它不能排除长会话或已挂载源会话的增长。Host 启动器另一个进程约占 55MiB RSS，直接相加仍会重复计算进程间共享页。

快照中各类节点的 shallow self size 如下。它包含部分原生 backing store 的表示，不是 RSS 分区，也不与上表 heapUsed 严格相等。

| 类型 | 大小 | 数量 |
| --- | ---: | ---: |
| 普通字符串 | 44.38MiB | 214,604 |
| 原生存储 | 23.47MiB | 1,384 |
| 数组 backing store 等内部数组 | 20.65MiB | 66,829 |
| 代码相关节点 | 20.18MiB | 199,424 |
| 对象本体 | 18.09MiB | 372,998 |
| 闭包 | 14.45MiB | 268,519 |
| 对象形状 | 5.50MiB | 64,274 |
| 其他内部节点 | 4.07MiB | 91,711 |

强引用 dominator 分析中，最大的对象持有者是 `ClientModuleRegistry`，retained size 约 **22.03MiB**；`KvTableImpl` 约 **2.57MiB**。它们所引用的 Map、Buffer、ArrayBuffer 已包含在 retained size 内，不能逐项重复相加。字符串切片包装节点自身很小，因此只看 shallow size 会漏掉它保住的巨大父字符串。

快照采集约 4.66 秒，节点约 134 万、边约 642 万。采集过程本身让 worker RSS 从 272MiB 增加到约 678MiB，而 JS 堆约为 125MiB；不能把这部分观察开销认作产品泄漏。原始堆图只在分析进程内处理，没有保存包含用户内容的快照；输出仅保留匿名计数、类型和大小。Inspector 已关闭，不应反复在线采集大快照。

## 3. 浏览器单个远端会话

桌面 Chromium 1440×900、实际既有远端会话、隔离布局、所有生产写入被阻止。使用正常只读状态流，无网络降速。正文和编辑器出现后静置 2 秒，先读取自然状态，再显式 GC 测留存。GC 放在打开计时结束之后；这些数字不是峰值，也不等于整个浏览器 RSS。

| 导航 | 自然状态 JS 堆 | GC 后 JS 堆 | GC 后 backing storage | GC 后 DOM 节点 / 监听器 |
| --- | ---: | ---: | ---: | ---: |
| 冷浏览器 | 137.70MiB | 112.60MiB | 33.68MiB | 6,660 / 1,240 |
| 第一次刷新 | 136.29MiB | 111.89MiB | 33.68MiB | 6,660 / 1,242 |
| 第二次刷新 | 189.97MiB | 111.71MiB | 33.68MiB | 6,660 / 1,240 |

三个 GC 后样本均有一个 Pane、105 个聊天节点、4,639 个页面元素。DOM 计数还包含非元素节点等，因此不等于 `querySelectorAll('*')`。CDP 报告的 embedder heap 约 10–11MiB，与 JS 堆和 backing storage 是不同统计口径，不合并成“浏览器总内存”。

这三次刷新没有显示留存递增；但单 Pane 约 112MiB 的 JS 基线仍重，不能当作已优化完成，也没有覆盖连续翻几百页、多 Pane、长期增量和关闭后的释放。当前 browser history release 还使用事件数阈值，不能约束单条大工具结果的字节量。

复现使用既有远端资源标识与本机 admission 文件，不把标识、正文或凭据写进报告：

```sh
HAPI_DSH_PROBE_MEMORY=1 HAPI_DSH_PROBE_RUNS=3 npm run test:perf:federated
```

另需通过环境设置 `HAPI_DSH_PROBE_SESSION`。此选项额外记录自然状态与 GC 后的 JS、backing storage、DOM 和监听器计数；普通性能探针不执行 GC。原始样本在本机 `/mnt/cache/data-cache/hapi-dsh-browser-memory/report.json`。

## 4. 其他开销与处理顺序

| 来源 | 已有证据 | 当前结论 |
| --- | --- | --- |
| 慢消费者队列 | 隔离的真实 rc.3 运行时：同会话同 key 的 2,000 条状态更新全部保留，逻辑载荷 8,230,000 字节 | 有积压风险；应对可覆盖的状态做合并或提供背压。不能丢弃有顺序要求的历史事件 |
| 取消与断连 | 100 次待处理 next/abort/return，25 次真实 loopback WebSocket 断连；结束后队列、监听器和绑定均为 0 | 本次未复现断连清理泄漏，不把它列为已证实根因 |
| Host 会话历史 | source service 保留已挂载 agent；Session.log、projector、内容/子代理索引随历史增长 | Pane 关闭不等于这些数据释放。需要独立的显示数据生命周期及总字节预算，同时保留原生执行所有权 |
| 子代理索引 | 已按真实旧源码复现累计正文留存；1024 次更新约 257MiB，修复后两条路径均不足 0.6MiB | 原始正文引用已移除；身份索引仍随行数线性增长，见 1b |
| 服务事件 Promise 队列 | 真实 CodexService 配合受控 transport/handler：阻塞首个消费者后，1024 份累计快照使堆从 19.16 增至 276.43MiB，排空后降至 27.31MiB；逐条消费对照也是 27.31MiB | 已复现、尚未修复。`eventWork.size=1` 不能反映链上的 1024 个闭包；8MiB journal 不约束这个队列。需要保持事件与生命周期顺序的合并/背压，不能直接丢弃队列 |
| 全量历史重建 | 读取新历史时旧 Session 仍存活，原始行、投影和序列化暂时共存；并发数上限不等于字节上限 | 需要按页/字节限制在途工作；仅移动到异步任务或 Worker 不会降低总内存 |
| 接收日志 | 每源最多 1,024 条 / 8MiB，另有最多 4,096 个小型驱逐凭据 | 已有单源边界；多源总量仍需预算，不能称为全局有界 |
| 磁盘历史缓存 | 154 个 history 文件，合计约 2,179.60MiB，最大约 235.78MiB | 这是磁盘量，不是 RAM；反映全量读取/解析可能很重。文件数不能当作活跃 agent 数 |
| 前端模块缓存 | 该次 Host 最大对象持有者约 22MiB；模块代际缓存有限 | 是明确的基线成本；本轮没有证据把它称为导致 4GB 的无界泄漏 |

优先级是先修复已重现的平方增长，再为显示会话建立按字节计算的留存预算、裁减索引中的正文、限制全量重建的在途字节，最后降低正常启动的插件/运行时基线。内存应随可见窗口、受限的后台缓存和在途数据增长，不能随所有曾经打开的会话或所有流式前缀永久增长。单纯提高 Node 堆上限、定时重启或把工作挪到 Worker 都不构成内存修复。

## 验收状态

字符串修复已通过类型检查、完整构建和全量逻辑测试（1,178 通过、1 跳过）。真实 pinned DSH 的三个浏览器用例通过：Codex/Pi 在初始历史与刷新请求阻塞期间保留实时后缀，刷新后恰好出现一次；最终消息正常收束。前两个旧用例最初等待侧栏会话自动挂载，因现有按需加载策略而失败；改成先通过真实侧栏点击打开，保留全部原历史竞争断言后通过，没有恢复全目录预加载。

四张合成桌面/手机截图已逐张查看，正文、输入框和单行底栏可读，无横向溢出。正式 Host 发布流程再次运行类型检查、全量测试和完整构建，并在确认普通 DSH 会话空闲后重启显示 Host。HAPI Hub 与原生执行未重启。客户端资源版本为 `7f47fbe83abd`；HTTP 与认证压缩 WebSocket 可用，发布前的三个机器身份全部重新在线。
