# HHPI 会话冷打开与持续阅读修复

本次修改把目标会话的读取从目录同步、编辑器可写状态和全量历史投影中分离。界面继续使用已安装的官方 Conversation、Chat、读者提交和导航；合法只读来源可以正常阅读，原生写入所有权、审批和队列继续由来源决定。

## 读取路径

Codex 使用来源侧原生 SQLite 历史索引定位消息，只取当前页所需的原生 item，再适配为官方事件。事件坐标来自原生 item ordinal 和有限事件种类，不再先遍历所有 turn 才裁出一页。上下文事件不推进正文游标。投影缓存按来源修订校验，历史改写会撤销旧代际，重复传输复用已有对象。

本机直接查原生索引；远端可配置只读 `historyMetadata` 辅助进程。辅助进程为每个来源保持一条 JSONL 通道，可复用 SSH 连接。调用者取消仅取消自己的等待；操作超时会回收失去响应的只读通道，下次查询重新建立。可执行文件和参数来自 Host 的私有配置，不接受浏览器指定命令。

DSH 使用获批三个包的可选索引读取契约，直接保留原始事件、序号和依赖。SQLite sidecar 保存位置和依赖元数据，不保存第二份正文。索引代际在追加和进程重启后稳定；替换或截断存档会产生新代际。页预算包含解释正文所需的完整上下文，无法放下时沿读取方向缩小正文页。

旧存档首次建索引仍需读取整个存档一次。原有格式规则现在可以逐段校验，在可取消的隔离 Worker 中建立索引。既有单个巨大压缩帧仍须完整解压该帧，不能把这一情况称为按页字节读取。默认持久层路径保持不变，HHPI 显式启用 `indexedReading`。

## 首屏、重连与缓存

目标身份可以直接解析，不再等待全机器目录完成。已知 DSH 原 Owner 的定位信息随读取修订保存，重启后只对该 Owner 在线续租；保存的定位信息不代表授权。首次从未发现过的 DSH 身份仍需经原 Owner 目录确认，删除、撤权和多 Owner 歧义不能通过缓存绕过。首屏以已提交且已恢复位置的官方阅读窗口为准，可选补页和写入限制不会撤销有效正文。写入能力恢复后沿用同一个编辑器和草稿。

同代际的订阅重放缺口保留已接受的历史，重新校验保留区间；真实代际变化才撤销旧正文。关闭最后一个 Pane 会暂停订阅，并在已有会话数和内存预算内保留近期历史。活动 Pane 受保护；持久缓存以事件表和页面引用去重，避免每页反复序列化同一正文。

大型工具输入、结果保留在来源，通过带会话范围及修订约束的现有资源接口按需读取。普通工具仍使用原官方视图；大工具使用官方 Tool slot 展示预览、分块详情和完整下载。来源的原始工具身份和内容不变。单条巨大普通正文或无法缩小的依赖闭包仍受既有传输预算约束，不承诺任意大小的单条记录。

## 验证范围

- 原生 SQLite 合成来源从空投影索引冷打开 2,048 轮；使用生产适配器和实际 SessionViewHost，只有原生 item RPC 边界是 fixture。
- 安装后的 DSH 包执行连续六次补页、工具依赖、并发追加、重启修订稳定、同数量存档替换以及取消/关闭后原生写入仍可用。
- 实际官方组件验证只读阅读、写入能力变化、同一编辑器草稿和大工具资源读取；桌面、手机视口共用两条有界浏览器场景。
- 发布使用原有正式 bundle 安装和健康检查，保留旧版本及回滚路径。源码测试、安装包、真实来源查询、站点浏览器和实体手机分别记录结果。

实验室和生产验收的最终记录另附；此文描述实现及边界，不把尚未执行的生产或实体设备检查当作通过。

最终实验室 Chromium 153.0.8010.12 结果见 [浏览器记录](hhpi-opening-browser-results-2026-11-04.json)：桌面 25.776 秒、手机视口 54.583 秒，均在原有单场景 60 秒内完成；每种视口连续 13 段历史提交锚点位移均为 0 像素。原生冷打开阶段从导航到首段正文分别为 903/969 毫秒，共读取 7 组原生正文。该来源包含 2,048 轮合成原生数据，不能将数值作为所有生产会话的承诺。

真实 Linux 与 Windows 来源的只读适配器探针也获得连续三段更早区间，代际保持稳定，未执行写入。一次最终测量的首读为 110/1418 毫秒，后两页为 48、44 / 207、95 毫秒，重复尾页均为 2 毫秒。这些是源端接口测量，包含新适配器连接建立，不是生产浏览器的打开耗时。
