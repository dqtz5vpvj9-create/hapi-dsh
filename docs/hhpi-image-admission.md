# HHPI image submission persistence

An image larger than about 1.5 MiB could be rejected as a full saved-message queue even when no message was pending. The native composer encodes images as base64; the outbox counted the resulting JSON as UTF-16 localStorage bytes against a 4 MiB text-journal budget. Raising that budget would still leave the browser's localStorage quota in the submission path.

Image operations now finish a transaction in the existing `hhpi-operations-v1` IndexedDB ledger before `RemoteSourceSession.prompt` accepts the prepared submission. Their localStorage entry is a small version-2 index containing the operation and session IDs plus delivery state. The full original operation, including image bytes, stays in the canonical ledger. Text-only admission remains synchronous. The HHPI operation format, image frame limits, execution owner and receipt reconciliation remain unchanged.

Reload restores image payloads before dispatching later messages. An already attempted operation queries its existing receipt; it does not resend because a view was reopened. Existing inline image journals migrate into the same transaction ledger. Session/account revocation includes image references whose payload read is still pending. The original source identity is retained throughout.

When local admission fails, the source Session retires its unsent pending echo with a failed outcome. The official editor keeps the draft and attachments. A failed local save therefore no longer leaves a transcript row that looks like a sent message. Composer image thumbnails use `object-fit: contain` so wide screenshots remain recognizable.

Regression coverage uses production outbox, Session and transaction logic with controlled storage/RPC boundaries. It covers a 2 MiB image under a 64 KiB per-entry localStorage quota, an image-only message, FIFO restoration before a later text, lost acknowledgement without resending, migration from an inline journal, late account changes, revocation during restoration/admission and failed admission removing its pending echo. Browser and publication results are recorded after the completed build is exercised.

The completed `npm run check` passed typechecking, 2,112 Node tests (four skipped), 53 component tests, all six fault injections and the build. The bounded desktop/mobile browser scenes use the pinned native editor, image serialization, browser IndexedDB and production outbox. Only source RPC and workspace persistence are synthetic. A 2,366,086-byte PNG reached the intercepted native operation, then the actual editor and attachment cleared. The localStorage journal was 321/320 characters and the empty composer measured 96/98 pixels. The desktop scene also reloaded an uncertain submission and queried its original receipt without sending again. Both contexts had zero page errors or blocked requests. No live model received the test image. These probes must load both the main UI and the independent session-provider build; substituting only the UI leaves the old sender active.
