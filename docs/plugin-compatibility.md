# 插件与原生会话

插件仍由官方 DSH 插件页管理，同一 Host 的所有 Pane 共用一张完整插件图。新建 Pane 不会复制插件服务。文件、Terminal、工具视图、设置和右栏沿用公开槽位；工具名称适配优先复用实际注册的官方组件；shell 别名只转换真实参数与结果，专有工具视图仍有优先权，不再自行绘制一套通用工具行。

启用插件时，先区分它改变的是界面还是 Agent 的执行能力。普通 DSH 会话由所属 Host 的 DSH Agent 执行；HHPI Codex 会话由原 Runner / 原生引擎执行，插件不能通过开启一个开关改变它的所有者。

| 插件功能 | 普通 DSH | HHPI / 原生 Codex |
|---|---|---|
| 插件市场、设置、开发者工具 | 保留官方页面和注册 | 页面保留；查看的是所属 Host 的插件，原始源数据通过源诊断入口查看 |
| 语音输入 | 官方输入流程 | 共享官方输入 owner 的本地识别把文字插入当前 Pane 草稿 |
| 思考翻译 | 官方 reasoning body 插槽及原会话翻译记录 | 同一官方插槽；来源翻译记录保存在所属 Host 的私有 sidecar，条件见下文 |
| 工具与产物视图 | 官方注册 | 对已投影的对应节点生效；缺失的原生内容不会补造 |
| 团队与任务看板 | DSH 团队插件 | 展示原源报告的团队/子代理；不把 DSH 团队工具注入 Codex |
| 自动授权 | DSH 权限与审查 | 使用原引擎权限与审批；不将插件审查结果当作原生授权 |
| Git worktree | DSH 创建/执行链 | 使用源机器的新建 worktree 能力；不会偷偷另起 DSH 会话 |
| 持久终端 | 官方 Terminal API | 公开 Terminal owner 组合真实源 OS 的 cwd 与 subprocess；旧 HAPI SessionTerminal 兼容运行时已退休 |
| 会话搜索 | DSH 会话检索工具 | UI 可搜索联合目录和源历史；Codex 自己的工具列表仍由原引擎决定 |
| 自动标题、徽章技能 | DSH 插件在执行时生效 | 保留源标题；没有把 DSH 的提示词插件附加到原生模型请求 |
| Ralph 循环 | 由 DSH 插件执行 | Codex 使用原生 Goal 入口；两者不互相冒充 |

以上是按当前公开接口核对的归属表，不是每个实验插件的生产验收报告。要让 DSH 的执行类插件也在 Codex 中运行，需要原引擎明确支持对应工具/事件接口；没有这条接口时，不能靠 UI 适配宣称兼容。

思考翻译要求所属 Host 安装同套当前源码扩展、启用官方 cot-translation bundle，并具有可用的已选翻译服务。官方 Reader 必须收到真实投影的 reasoning 内容；展开时才翻译，原文保持可用。普通 DSH 继续使用原会话 writer；HHPI 来源使用按认证 principal 与完整来源 ID 隔离的翻译 request/result 存储，逐次复核来源权限，不激活 DSH Agent，也不改写原生 thread。

中央 Codex 来源使用中央的 Client graph、controller、翻译偏好和来源 gateway。配对 Host 的普通 DSH Pane 使用该 Host 自己的插件图与偏好；中央启用插件不会向其他 Host 传播开关或配置。Runner 的同版发行身份检查仍须通过。四包扩展的必要性、默认行为与测试边界见[插件委托 ADR](adr/hhpi-plugin-session-delegation.md)；源码、安装、浏览器和真实服务的验证各自记录。

维护约束：优先使用官方插件与公开契约；必要的 DSH 扩展按[当前源码扩展流程](hhpi-extension-install.md)保留默认路径、源码归档与验证，不改编译产物。不覆盖专有工具的图片、问题或审批视图，不复制原生执行、不导入历史伪装成新对话，不自动重放未知结果的操作。
