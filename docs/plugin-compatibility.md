# 插件与原生会话

插件仍由官方 DSH 插件页管理，同一 Host 的所有 Pane 共用一张完整插件图。新建 Pane 不会复制插件服务。文件、Terminal、工具视图、设置和右栏沿用公开槽位；工具名称适配优先复用实际注册的官方组件；shell 别名只转换真实参数与结果，专有工具视图仍有优先权，不再自行绘制一套通用工具行。

启用插件时，先区分它改变的是界面还是 Agent 的执行能力。普通 DSH 会话由所属 Host 的 DSH Agent 执行；HAPI/Codex 会话由原 Runner / 原生引擎执行，插件不能通过开启一个开关改变它的所有者。

| 插件功能 | 普通 DSH | HAPI / 原生 Codex |
|---|---|---|
| 插件市场、设置、开发者工具 | 保留官方页面和注册 | 页面保留；查看的是所属 Host 的插件，原始源数据通过源诊断入口查看 |
| 语音输入 | 官方输入流程 | HAPI 语音桥向当前 Pane 的官方 composer 插入文本与附件 |
| 思考翻译、工具与产物视图 | 官方注册 | 对已投影的对应节点生效；缺失的原生内容不会补造 |
| 团队与任务看板 | DSH 团队插件 | 展示原源报告的团队/子代理；不把 DSH 团队工具注入 Codex |
| 自动授权 | DSH 权限与审查 | 使用原引擎权限与审批；不将插件审查结果当作原生授权 |
| Git worktree | DSH 创建/执行链 | 使用源机器的新建 worktree 能力；不会偷偷另起 DSH 会话 |
| 持久终端 | 官方 Terminal API | 机器终端走源桥；旧 session terminal 保留旧协议语义 |
| 会话搜索 | DSH 会话检索工具 | UI 可搜索联合目录和源历史；Codex 自己的工具列表仍由原引擎决定 |
| 自动标题、徽章技能 | DSH 插件在执行时生效 | 保留源标题；没有把 DSH 的提示词插件附加到原生模型请求 |
| Ralph 循环 | 由 DSH 插件执行 | Codex 使用原生 Goal 入口；两者不互相冒充 |

以上是按当前公开接口核对的归属表，不是每个实验插件的生产验收报告。要让 DSH 的执行类插件也在 Codex 中运行，需要原引擎明确支持对应工具/事件接口；没有这条接口时，不能靠 UI 适配宣称兼容。

维护约束：不修改 DSH 源码，不覆盖专有工具的图片、问题或审批视图，不复制原生执行、不导入历史伪装成新对话，不自动重放未知结果的操作。
