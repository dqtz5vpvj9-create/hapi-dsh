# Keep mounted rows when older bodies arrive after a dependency prefix

A history feed can retain a control at index zero while inserting older bodies between it and the visible rows. `VirtualChatRows` currently recognizes only uniform index shifts, so it briefly replaces resident body seats with the old numeric viewport's unrelated rows before the official landing corrects the range. The actual before-page trace shows two large mounting/layout passes in one publication.

Recognize source-order-preserving growth across the mounted keys, including nonuniform forward shifts. Keep those seats until the existing official programmatic/native offset observer releases the range. A true deletion, backward shift or reorder clears it; explicit navigation and all measurement/capacity/correction contracts remain in force. No new API or history budget is required.

The regression fails on the old implementation by observing resident DOM seats disappear. It checks retained element identity, release at the official landing, actual reorder/deletion, and existing real-content height/hidden/resize/navigation behavior. Installed geometry and the 80 ms frame budget remain separate acceptance checks.
