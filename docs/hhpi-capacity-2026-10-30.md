# Continuous history capacity failure, 2026-10-30

The user's mobile screenshot reports `CAPACITY_EXCEEDED` during ordinary upward reading. The previous prepend-anchor correction did not remove cumulative admission ceilings. The six-page browser check only reached 1,120 logical nodes, below the coordinator's 2,000-node envelope; it could not establish that longer reading remained possible.

The new real-assembler regression reproduces a rejection at 2,080 nodes on the previous source build. A read-only production diagnostic then reproduces the visible error after fifteen successful earlier pages, at the sixteenth request, on both desktop and mobile. Those diagnostic scenarios took 26.84 and 38.14 seconds. Raw reports remain local; source bodies and credentials are not written to reports.

The fix separates newly admitted content from retained history. Complete-window readers charge new/revised source entries and stable derived Context identities against the unchanged admission limits. The HHPI provider retains accepted contiguous pages instead of trimming their opposite edge to satisfy an opening envelope. Default bounded-window hosts retain their original absolute limits. See [the admission ADR](adr/hhpi-continuous-admission.md) and [upstream proposal](upstream-pr-continuous-admission.md).

The second screenshot is a different failure: a preserved legacy reference calls `sourceSessionResolve`, which the HAPI-free workspace shell did not register. The shell now returns a typed `source_not_connected` rejection. The client presents that state directly instead of waiting for a missing service. This preserves the saved reference; it does not attach the absent source or establish that its original body is readable. The current Host advertises two Codex sources; the saved Redmi conversation is not advertised by those sources.

The production probe now checks tool-only intervals by exact call identity plus visible source name. An unrelated tool call with the same name cannot count as newly read content. A prepend within one large process group need not change its virtual row index, so the probe also observes the official paging control's completion after commit/correction. Any history error still fails the scene. Earlier diagnostic failures caused by the user/assistant-only probe and index-only checkpoint are retained and are not counted as product regressions or successful acceptance.

The source-level contracts cover forty pages and 6,400 continuous bodies, independent Panes, return to the resident tail, live revisions beyond the old ceiling, default-mode rejection and genuine oversized-page rejection. The browser component fixture contains fourteen complete tool-bearing source windows and checks thirteen prepends, taking the actual installed Chat from 154 to 2,156 logical nodes.
