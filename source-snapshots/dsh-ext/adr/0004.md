# ADR 0004: programmatic live-edge landings re-enter tail following

## Context

The stock reading policy only re-enters `followingTail` when a scroll sample
that reaches the live edge is attributed to a reader gesture
(`scroll.movedByReader`). A script or layout landing that parks the reader
exactly on the live edge therefore stays out of following: appended rows are
rendered below the viewport, where the virtualized chat flow never mounts them.
HAPI-DSH composition needs live streaming to remain visible in that case.

## Decision

Add an opt-in module switch `setFollowOnProgrammaticEdge(enabled)` in
`use-chat-reading`. When enabled, a sample whose `top` is within 1px of the
floor re-enters following even without a reader gesture. Default is `false`, so
stock behavior and every existing consumer remain byte-identical; the switch is
enabled only by the hosting composition, either through this setter or by marking the document root with the generic `data-dsh-follow-edge` attribute.

## Consequences

- Programmatic or restored scrolls to the live edge now follow new output.
- Reader-owned movement semantics are unchanged; the non-following branch still
  prevents appends from stealing the reading position.
- Disabling the switch restores the stock path without code changes.

## 0.2.2-rc.1 follow-up: preserve a saved semantic seat

The rc.3 decision and patch above remain historical inputs. The current HHPI
cohort carries the opt-in into DSH `0.2.2-rc.1` at upstream
`66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`; this section records its narrower
ownership rule without changing the archived rc.3 patch.

A real result reveal established a non-following semantic anchor, then expanding
its pane changed the viewport from 134px to 1,149px. A virtual range temporarily
unmounted the target and reduced scroll height, so the browser clamped the old
scroll position to its temporary floor. Treating that non-reader sample as an
intent to follow cleared the saved anchor. Reaching a temporary layout floor is
not sufficient evidence that the reader chose Latest.

When a semantic position is already saved and tail following is off,
`useChatReading.onScroll` leaves a non-reader sample to the existing layout
restoration owner. It does not begin or cancel a reader sample or clear the
anchor. Real reader movement, explicit Latest/followTail, the existing
unanchored programmatic-edge opt-ins and pending reader samples retain their
previous behavior. No new switch, geometry reader, timer or public API is added.

The production Hook, ChatReading, ChatViewport and ScrollFollow fixture fails
before this guard: the layout clamp changes followingTail to true. Ten focused
DOM contracts pass after it, including explicit Latest, real reader movement,
unanchored opt-ins, and restored anchorTop24; strict source/test types pass.
The geometry and observer deliveries are controlled test boundaries. Actual
search/Zoom/Return and performance acceptance remain separate; this does not
attribute or pass the formal 390px 100ms result against the unchanged 80ms
budget. The implementation and validation were supplied by the native-reading
owner and are combined with the range-only geometry correction for cohort .19.
