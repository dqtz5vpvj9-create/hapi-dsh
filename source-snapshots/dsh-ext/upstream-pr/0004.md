# Window chat rows while preserving the viewport's reading anchor

## Problem

Long HAPI transcripts can render hundreds of DSH rows for one source page. The current Chat flow mounts every loaded row, so prepending history can create long main-thread stalls and make a normal upward scroll feel like a scene change.

## Change

Use the existing TanStack virtualizer at the official Chat flow boundary. It measures dynamic row heights, renders the visible range with overscan, and pins the current reading row, navigation destination, focused row, and retained expanded groups. The Chat viewport remains the sole scroll owner; semantic row keys keep the reader anchored when a prepend shifts indices. Upward gesture automation and source-page warming remain in the HAPI DSH host integration.

## Validation

Focused client tests cover anchor preservation across a prepend, bounded mounted rows in a long transcript, focused/expanded-row retention, dynamic-height measurement, and official loading-control ownership. HAPI DSH contract tests cover single-flight page warming and retry after a failed speculative read. Browser and physical-device smoothness are release acceptance checks, separate from these component tests.

This is a draft for upstream review and has not been submitted.

## Current rc.1 follow-up: a layout clamp does not choose Latest

The original rc.3 draft above remains unsubmitted history. For the current
DSH `0.2.2-rc.1` source cohort, preserve a saved semantic position when a
non-reader scroll reaches a temporary floor during pane resize or virtual
range changes. Previously the programmatic-edge opt-in could adopt that clamp
as tail-following and discard the revealed row's anchor.

Apply the ownership check in the existing reading hook, before sampling a
non-reader scroll. Preserve real reader movement, explicit Latest/followTail,
unanchored programmatic-edge opt-ins and pending reader samples. No new public
API, timer, scroll owner or observer is introduced. The native-reading owner's
production Hook/Viewport/ScrollFollow regression fails on the old policy and
passes ten focused DOM cases with strict source/test types. Browser search,
Zoom/Return and the unchanged 80ms reading budget still require actual-path
acceptance after the combined .19 installation. This draft has not been sent
upstream.
